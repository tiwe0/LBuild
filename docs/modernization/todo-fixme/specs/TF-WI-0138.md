# TF-WI-0138: Local wild-inferiors suffix traversal contract

## Scope

This specification removes the former local-filesystem restriction that
required `:WILD-INFERIORS` to be the final directory element.

## Required behavior

- `:WILD-INFERIORS` matches zero or more directory levels at any position in an
  absolute local directory pattern.
- Components following `:WILD-INFERIORS` are evaluated normally. They may be
  exact strings, wildcard strings, `:WILD`, or another supported directory
  component.
- A directory-only `:WILD` component enumerates the current directory's
  children only when it is the final pattern component. When followed by a
  suffix, it consumes exactly one directory level and evaluates that suffix in
  each matching child.
- Zero-level matching is included, so `(:ABSOLUTE :WILD-INFERIORS "src")`
  finds both a root `src` directory and nested `src` directories.
- Recursive traversal terminates at leaf directories, and duplicate pathnames
  arising from equivalent wildcard decompositions are removed by the existing
  `DIRECTORY` result contract.
- Directory-only recursive queries return the canonical pathname of every
  actual matched directory, not the wildcard query pathname. Thus root `src`
  and `vendor/src` remain distinct through result de-duplication.
- A pathname directory of `:WILD` retains its existing canonical meaning of
  `(:ABSOLUTE :WILD-INFERIORS)` and passes the same absolute-path validation.

## Test-before evidence

Against the baseline source, the isolated `FILE_LOCAL_CASE=0138` focused host
contract failed with `SIMPLE-FILE-ERROR` and
`:WILD-INFERIORS must be the final directory element`.

A review regression added before the directory-result fix failed with
`Directory-only :WILD-INFERIORS suffix matching`: expected canonical
`(:ABSOLUTE "src")` and `(:ABSOLUTE "vendor" "src")`, but received only the
original `(:ABSOLUTE :WILD-INFERIORS "src")` query pathname.

A second review regression added before the intermediate-`:WILD` fix failed
with `Directory-only intermediate :WILD matching`. The query
`(:ABSOLUTE :WILD-INFERIORS :WILD "core")` returned unrelated directories
because `:WILD` enumerated immediately and ignored `"core"`, rather than
returning only canonical `src/core` and `vendor/src/core` pathnames.

## Acceptance evidence

`Lambda64/tests/host/test-file-local-semantics.sh` directly executes the
production traversal with exact and `:WILD` suffixes after
`:WILD-INFERIORS`, covering both zero-level and nested matches. The focused
host test additionally verifies that the directory-only suffix query retains
both root and nested matches as canonical pathnames. It also covers a
directory-only intermediate `:WILD` followed by `"core"`, requiring only the
two actual canonical `core` matches with `NAME` and `TYPE` `NIL`, version
`:NEWEST`, and no wildcard components. The focused host test must pass.

The work item remains active until the required guest and integration levels
run the equivalent queries on a booted Lambda64 `LOCAL:` hierarchy.
