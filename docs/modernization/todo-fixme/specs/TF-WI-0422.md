# TF-WI-0422 — 标准流参数的开放状态校验

- **基线标记：** `TF-occ-82d839aa4a98c7c38d262d40`
- **代码事实源：** `Lambda64/system/stream.lisp:170`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`frob-stream` 在接受显式流对象前必须验证其仍处于打开状态。`nil` 仍选择调用方
提供的默认流，`t` 仍选择 `*terminal-io*`；打开的流按原样返回，已关闭的流必须
以该流为 `:stream` 关联数据发出 `stream-error`。非流参数继续由 `check-type` 报
`type-error`。

## 先测试证据

新增 `Lambda64/tests/host/test-system-stream-open-state.sh`。测试从生产源提取实际
`frob-stream` 定义，使用打开和关闭的最小流替身以及独立的 `open-stream-p` 泛型
验证参数归一化。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-stream-open-state.sh
```

失败并报告 `closed stream was accepted`，证明原实现只检查对象类型，没有检查开放
状态。

## 验收标准

1. `nil` 和 `t` 保留原有默认流及终端流语义。
2. 打开的流按同一对象返回，关闭流发出携带该流的 `stream-error`。
3. 非流值仍发出 `type-error`，不因新增检查而改变类型校验边界。
4. host 测试直接加载生产定义，并以将 `open-stream-p` 强制替换为真值的变异负例
   锁定关闭流拒绝路径；cold image 与 QEMU integration 在后续完整测试阶段补齐。
