# TF-WI-0150: TGSI immediate data-type contract

## Scope

This specification resolves the `UINT32`, `INT32`, and `FLT64` immediate gaps
in `Lambda64/gui/virgl/tgsi.lisp`. Existing `FLT32` behavior remains supported.

## Required behavior

| Lisp type tag | Arity | Element contract | TGSI text |
| --- | ---: | --- | --- |
| `:flt32` | 4 | `single-float` | `FLT32` |
| `:uint32` | 4 | `(unsigned-byte 32)` | `UINT32` |
| `:int32` | 4 | `(signed-byte 32)` | `INT32` |
| `:flt64` | 2 | `double-float` | `FLT64` |

All four forms consume one immediate token and four data tokens. Each `FLT64`
value occupies two data tokens. Because Common Lisp prints double-float
exponents with `D` while Mesa's C numeric reader requires `E`, `FLT64` output
normalizes the exponent marker without changing the value.

Wrong arity, an unsupported type tag, or a value outside the stated element
type fails before the assembled shader is returned.

## Test-before evidence

Before implementation, the focused fixture reached an assertion requiring
`:flt32`; `:uint32`, `:int32`, and `:flt64` could not be emitted. The old
four-element destructuring also could not represent the two-value `FLT64`
layout.

## Acceptance evidence

`Lambda64/tests/host/test-virgl-tgsi-parser.sh` verifies all four output forms,
unsigned and signed 32-bit boundaries, two double-precision values with
TGSI-compatible exponent spelling, exact token accounting, and rejection of
negative unsigned values, signed overflow, and four-value `FLT64` input.

The focused host test, `make lisp-style-check`, and a whitespace-clean diff are
required for this slice. The ledger additionally requires guest evidence from
the virgl/Mesa parser and shader-creation path. That environment has not been
run for this slice, so the work item must not be marked verified.
