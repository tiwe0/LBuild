# TF-WI-0356 — `&WHOLE` 的解构模式

- **基线标记：** `TF-occ-b305c22e5eb2d3546688eb8d`
- **代码事实源：** `Lambda64/system/defmacro.lisp:36-49`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`expand-destructuring-lambda-list` 对 `&whole` 后的 cons pattern 使用已有的
`handle-sublist` 路径，而不是把 list 当成 `let*` 变量名。这样嵌套 macro lambda-list
可用 `&whole` 解构完整子表达式；普通 symbol 的 `&whole` 绑定保持不变。

## 先测试证据

新增 `Lambda64/tests/host/test-system-defmacro-whole-destructuring.sh`，从生产源提取
实际展开器，在最小 Common Lisp 支撑中执行其生成的 expansion。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-defmacro-whole-destructuring.sh
```

失败并报告：

```text
(OPERATOR ARGUMENT) is not a symbol and cannot be used as a local variable.
```

证明旧实现把 `&whole` 的 pattern 错作为局部变量绑定。回归覆盖完整内层表单的成功解构、
结构不匹配的失败路径；变异负例恢复旧的直接绑定行为，必须被测试拒绝。

## 验收标准

1. 嵌套 `(&whole (operator argument) &rest rest)` 可将完整子表单解构为两个绑定。
2. `&whole` pattern 结构与待匹配子表单不同时必须报错。
3. `&whole` 后为 symbol 的现有绑定路径不改变。
4. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。
