# TF-WI-0428 — XP `~A` / `~S` 字段参数

- **基线标记：** `TF-occ-1ae62362f38f5bc16d37b802`
- **代码事实源：** `Lambda64/system/xp-format.lisp:349`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

完成 XP compiled FORMAT 中 `~A` 与 `~S` 的
`mincol,colinc,minpad,padchar` 字段语义，并与早期 `mezzano.format` 的
同一实现保持一致。`@` 必须将整个补齐字段置于左侧，`:` 对 `NIL` 的
`()` 拼写不能回归。

## 先测试证据

实现前，以下断言在旧实现中失败：旧 XP handler 虽解析参数，却只执行
`write+`，因此 `~10A` 输出 `"x"` 而不是 `"x         "`；早期 FORMAT
同样没有实施这组参数。

```sh
bash Lambda64/tests/host/test-system-format-semantics.sh
bash Lambda64/tests/host/test-system-xp-format-justification.sh
```

## 验收标准

1. `minpad` 先提供最小 padding，随后按正的 `colinc` 增加，直到宽度至少
   `mincol`；默认值分别为 `0, 1, 0, #\Space`，且逗号占位的省略参数也必须
   归一化为这些默认值。
2. `~A`、`~S`、`:` 与 `@` 的组合，以及 `V` 动态参数均按上述规则工作。
3. 早期 formatter 在向 directive/block 传递剩余参数前，先消费 `V`/`#`
   参数，避免将控制参数误作待打印对象或迭代输入。
4. 非法 `mincol`、`minpad`、`colinc` 与 `padchar` 在两条 FORMAT 路径均拒绝。
5. host 回归覆盖早期 FORMAT 和实际 `formatter-fn` 生成的 XP 代码；其后
   通过 cold-image 与集成测试补充目标环境证据。
6. 仅在实现与验证完成后移除基线 TODO。

## 当前证据

`test-system-format-semantics.sh` 覆盖早期 `~A`/`~S` 的默认与自定义字段、
`@`、`:`、动态 `V` 参数、无效数值参数，以及 `~v{...~}` 的参数消费顺序；
变异负例覆盖 padding、`colinc`、左填充、`:`、`~S` escape 与 directive/block
参数消费顺序。

`test-system-xp-format-justification.sh` 通过实际 `FORMATTER-FN` 生成的 XP
handler 覆盖同一字段行为，并拒绝 shared-helper、参数次序和 modifier/escape
转发的变异。`make test-fast` 已通过；cold-image 与 QEMU 集成测试仍未执行，
故工作项保持 `active`。
