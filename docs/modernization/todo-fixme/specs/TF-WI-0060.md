# TF-WI-0060 — Unbox PHI type separation

- **Code source of truth:** `Lambda64/compiler/backend/passes.lisp:120-153`
- **Risk:** low
- **Required test levels:** host, cold-image, integration

## Objective

The `unbox-phis` pass must not treat `FIXNUM` as a subtype of
`UNSIGNED-BYTE-64`: fixnums can contain negative values. The existing `cond`
keeps the two representations separate and only accepts matching predecessor
types.

## Focused evidence

```sh
bash -n Lambda64/tests/host/test-compiler-unbox-phis-fixnum-u64.sh
bash Lambda64/tests/host/test-compiler-unbox-phis-fixnum-u64.sh
```

The host contract checks both type branches and rejects a mutation that enables
the disabled mixed `FIXNUM`/`UNSIGNED-BYTE-64` path. Cold-image and QEMU
integration remain pending.
