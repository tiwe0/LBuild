# TF-WI-0060: x86 MOVZX32 operand direction boundary

## Scope

Document the historical FIXME in `Lambda64/compiler/lap-x86.lisp` concerning
operand order for the `movzx32` pseudo-instruction.

## Contract

`movzx32` is the backend's 32-bit move used when a 32-bit value must be
materialized in a 64-bit virtual register.  The destination is intentionally
encoded in ModRM's `r/m` field and the source in the `reg` field using opcode
`0x89` (`MOV r/m32,r32`).  A 32-bit write zero-extends the destination in
64-bit mode; changing to opcode `0x8B` or swapping operands would reverse the
assignment and break byte-swap lowering.

## Verification

`Lambda64/tests/host/test-compiler-lap-x86-movzx32-direction.sh` checks the
encoding anchors and rejects reversing the ModRM operands/opcode.
