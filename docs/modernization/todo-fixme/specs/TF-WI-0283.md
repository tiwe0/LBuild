# TF-WI-0283 — Store freelist regeneration cleanup

## Scope

`regenerate-store-freelist` allocates a conservative number of metadata pages
and store blocks before serializing the rebuilt freelist. Any entries that are
not consumed by the used-block chain must be released before returning.

## Implementation

The finalization path already walks `free-block-list`, calling `free-page` and
`store-free` for every over-allocated pair. The former FIXME was stale; the
comment now documents this ownership and the conservative extra block.

## Acceptance evidence

`Lambda64/tests/host/test-supervisor-store-regenerate-freelist-cleanup.sh`
extracts the function, verifies both reclamation calls and their finalization
placement, and rejects a mutation that removes the cleanup loop. Cold-image and
integration evidence remain pending because this path requires the guest store
and VM lock.
