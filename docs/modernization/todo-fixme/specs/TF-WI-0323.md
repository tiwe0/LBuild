# TF-WI-0323 — 无效 Unicode 字符名称的码点校验

- **基线标记：** `TF-occ-24df1374ad33116132faf309`
- **代码事实源：** `Lambda64/system/character.lisp:500`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`name-char` 对 `UXXXX` 和 `UXXXXXXXX` 形式的 Unicode 名称必须在调用字符构造器前
验证码点范围。超出 `char-code-limit` 的值、UTF-16 surrogate 与 Unicode noncharacter
都应与未知字符名一致地返回 `nil`；合法 BMP 及带修饰位的 Unicode 名称保持原行为。

## 先测试证据

新增 `Lambda64/tests/host/test-system-character-unicode-codepoints.sh`。测试从生产源
提取实际 `name-char` 定义，覆盖合法 BMP/带 modifier、surrogate、noncharacter、
`U00110000` 和八位超界值。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-character-unicode-codepoints.sh
```

在 `U00110000` 处失败并泄出 `type-error`，因为旧代码把超范围整数直接传给内部
字符构造器。

## 验收标准

1. 合法 `UXXXX` / `UXXXXXXXX` 名称仍返回对应字符并保留修饰位。
2. surrogate、noncharacter 与大于等于 `char-code-limit` 的码点均返回 `nil`，不泄出
   内部构造器的类型错误。
3. 范围检查发生在调用 `make-character` 之前，已有构造器继续负责有效范围内的
   scalar-value 过滤。
4. host 测试直接加载生产定义，并以移除范围门卫的变异负例锁定超界输入路径；cold
   image 与 QEMU integration 在后续完整测试阶段补齐。
