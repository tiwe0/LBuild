# TF-WI-0397 — bit-vector 的 `SXHASH`

- **基线标记：** `TF-occ-453eccb84ea769307600eb89`
- **代码事实源：** `Lambda64/system/hash-table.lisp:652-678`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`SXHASH` 必须按 bit-vector 的逻辑 bit 序列计算稳定哈希，而不能为所有 bit-vector 返回
常量 `0`。实现使用与字符串哈希一致的 32 位 DJB2 风格混合，并纳入 vector 长度；它仅依赖
`bit` 访问，因此不依赖具体 backing storage。相等的 bit-vector 必须得到相同哈希。

## 先测试证据

新增 `Lambda64/tests/host/test-system-bit-vector-sxhash.sh`，从生产源提取
`hash-bit-vector` 与 `sxhash-1`，在 host Lisp 中验证相等副本、单 bit 改动和长度变化的
哈希行为。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-bit-vector-sxhash.sh
```

失败，因为生产源不存在 `hash-bit-vector`，且 `sxhash-1` 的 bit-vector 分支固定返回
`0`。变异负例恢复该常量分支；测试必须拒绝变异。

## 验收标准

1. 内容相等的两个 bit-vector 得到相同 `sxhash-1` 结果。
2. 选定样本中单 bit 改动和长度改动会影响哈希；非空输入不再固定为 `0`。
3. 哈希通过逻辑 `bit` 序列计算，不假设简单或特定物理表示。
4. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。

## 当前证据

```sh
bash Lambda64/tests/host/test-system-bit-vector-sxhash.sh
```

两项均已通过；后者同时确认恢复常量 `0` 分支的变异被拒绝。尚未执行 cold image 或 QEMU
