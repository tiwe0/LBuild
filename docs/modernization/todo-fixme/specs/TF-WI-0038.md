# TF-WI-0038: Close x86 single-float equality condition contract

## Scope

Baseline occurrence `TF-occ-49d05c0832af149c222ebd52` at
`Lambda64/compiler/backend/x86-64/number.lisp:1273` documents the conditions
needed by `sys.int::%%single-float-=`.

## Contract

`ucomiss` sets PF for unordered (NaN) operands and ZF for unordered or equal
operands. The lowering therefore starts with true, clears it on PF, and clears
it on NE (`cmov64p` followed by `cmov64ne`), yielding true only for ordered
equality. Both operands and the result remain represented by the existing
boxing/unboxing conventions.

## Verification

`Lambda64/tests/host/test-compiler-x86-float-equality.sh` checks the lowering
anchors, executable NaN semantics, and rejects a mutation that removes the PF
guard.
