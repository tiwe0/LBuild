# TF-WI-0003: Telnet UTF-8 input contract

## Scope

This work item replaces byte-at-a-time character conversion in the Telnet
receive path. It is implemented together with TF-WI-0004 so that only Telnet
payload bytes reach the UTF-8 decoder. The shared state-machine design is
[`telnet-nonblocking-receive.md`](../designs/telnet-nonblocking-receive.md).

## Required behavior

- Decode only framed Telnet data after NVT CR/NUL handling; IAC commands,
  negotiation options, and subnegotiation payloads never enter the decoder.
- Preserve partial one- through four-octet UTF-8 sequences across non-blocking
  feeds and deliver a character only after its complete sequence arrives.
- Match the existing external-format valid-scalar and U+FFFD replacement
  behavior for invalid, non-scalar, and truncated input.
- On EOF, emit exactly one replacement character for a pending UTF-8 sequence,
  reset decoder state, and emit nothing further for repeated EOF.

## Acceptance evidence

Host tests must cover every split point for valid UTF-8, invalid leaders and
continuations, Telnet IAC escaping, CR/NUL, and EOF. Guest and local integration
evidence described in the shared design are required before this work item can
be recorded as verified.
