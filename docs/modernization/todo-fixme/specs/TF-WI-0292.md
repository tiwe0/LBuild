# TF-WI-0292 — virtio-block 逻辑块大小

- **基线标记：** `TF-occ-6ef4c94e1c165fcf784a3255`
- **代码事实源：** `Lambda64/supervisor/virtio-block.lisp`
- **风险：** critical
- **要求测试层：** host、cold-image、integration

## 目标

当设备提供 `VIRTIO_BLK_F_BLK_SIZE`（feature bit 6）时，驱动在配置 virtqueue 前协商该
feature，并从配置空间读取 `blk_size`。上层磁盘接口以该逻辑块大小公开容量和 I/O；
virtio request 的 `sector` 字段仍按规范使用 512 字节单位，data descriptor 长度则使用实际
逻辑块大小。未提供 feature 或配置值无效时保持既有 512 字节行为。

## 先测试证据

新增 `Lambda64/tests/host/test-supervisor-virtio-block-blk-size.sh`，锁定 feature bit、协商、
512 字节 request-sector 换算、实际 data 长度和公开容量换算。实现前运行：

```sh
bash Lambda64/tests/host/test-supervisor-virtio-block-blk-size.sh
```

旧实现缺少 feature 协商并固定以 512 字节计算 data 长度，因此测试失败。变异负例同时移除
feature 协商并恢复固定 512 字节长度，必须被测试拒绝。

## 验收标准

1. 仅在设备提供 bit 6 时设置 `VIRTIO_BLK_F_BLK_SIZE` driver feature。
2. 逻辑块大小为 512 的设备行为保持不变；有效的 1024/2048/4096 字节块被正确公开。
3. request `sector` 为逻辑 LBA 乘以 `blk_size / 512`，descriptor 长度为
   `count * blk_size`。
4. 公开 sector 数为 `capacity * 512 / blk_size` 的整数部分，避免构造比例数。
5. 小于 512、大于 4096、非二次幂或非 512 倍数的配置安全回退到 512。
6. cold image/QEMU integration 待完整环境验收，保持 `active`。

## 当前证据

```sh
bash -n Lambda64/tests/host/test-supervisor-virtio-block-blk-size.sh
bash Lambda64/tests/host/test-supervisor-virtio-block-blk-size.sh
```
