# TF-WI-0136: HTTP unknown-host file error contract

## Scope

This specification closes the unresolved-domain failure gap in
`Lambda64/file/http.lisp`. It applies to initial requests and followed
redirects made by the HTTP file-system host.

## Required behavior

- The HTTP request path resolves the requested domain explicitly before it
  opens a TCP stream.
- Resolution uses the network resolver's non-signalling mode. A missing result
  is translated into `SIMPLE-FILE-ERROR`, preserving the file pathname supplied
  by `OPEN-USING-HOST` and identifying the unresolved domain in the report.
- No connection is opened and no request bytes are written after resolution
  fails.
- Successful resolution preserves the original domain in the HTTP `Host`
  header while the resolved address is used for the TCP connection.
- Redirect requests use the same error translation and retain the original
  file pathname as file-operation context.

## Test-before evidence

Before implementation, the focused test substituted the baseline
`HTTP-REQUEST` form while retaining the current parser fixture. With the
resolver returning no address, that form proceeded as though it could open a
stream and returned a response; the test failed with
`Unknown HTTP host did not signal`.

## Acceptance evidence

`Lambda64/tests/host/test-file-http-remote-paths.sh` supplies an unresolved
domain through the real request form and verifies the condition type, pathname,
domain report, non-signalling resolver argument, and absence of stream I/O. It
also verifies that a successful resolution connects to the resolved address
while retaining the original domain in the `Host` header. A dynamic
`OPEN-USING-HOST` redirect fixture issues an initial 302 followed by a 200 and
verifies that both calls receive the identical original pathname context.

The focused host test, `make lisp-style-check`, and a whitespace-clean diff are
required for this slice. A guest DNS failure and an integration HTTP open are
still required by the ledger; no such evidence is recorded here, so this item
remains active.
