# TF-WI-0071: Function-reference fast and full path ABI

## Scope

This specification defines the x86-64 fref fast/full paths, the arm64 indirect
path, and the GC and retargeting boundaries documented in
`Lambda64/doc/internals/abi.md`.

## Required documentation contract

On x86-64, named calls and jumps target the fref code area with a signed 32-bit
PC-relative fixup. The fref begins with padding and a five-byte relative jump.
An ordinary compiled function activates the fast path by pointing that jump at
the function entry point. Unbound frefs, closures, and other funcallable objects
activate the full path by setting its displacement to zero; the fall-through
code loads the fref `function` field into `RBX` and jumps indirectly through the
target entry point.

An unbound fref points its `function` field at itself, while its first word names
the undefined-function entry point. The GC scans a direct target reconstructed
from the active branch displacement. Arm64 has no direct fast path: `named-call`
loads the fref, target object, and target entry point before `blr`.

The ABI guide must preserve the implementation limitation in
`Lambda64/system/runtime-support.lisp`: retargeting currently lacks an fref lock,
explicit fences, and cross-CPU synchronization, so concurrent definition
replacement is not documented as an atomic transition.

## Test-before evidence

Before the documentation change, the ABI guide contained only a marker asking
for the fast and slow paths to be expanded. It described arm64 and undefined
functions but omitted the x86-64 branch layout, activation rules, GC handling,
and retargeting limitation.

## Acceptance evidence

The following static checks bind the description to the assembler, runtime, and
collector implementations:

```sh
rg -n 'Named direct jump to an FREF|note-fixup fref' Lambda64/compiler/lap-x86.lisp
rg -n '%activate-function-reference-(fast|full)-path|FREF should be locked|Cross-CPU synchronization' Lambda64/system/runtime-support.lisp
rg -n 'rel-target|Reconstruct the object and scan it' Lambda64/system/gc.lisp
rg -n 'define-macro-instruction named-(call|tail-call)' Lambda64/compiler/lap-arm64.lisp
```

`make docs-check` and `git diff --check` validate the documentation and patch
integrity. No machine code is changed by this documentation-contract work item.
