# TF-WI-0145: Asynchronous compositor window-kind query contract

## Scope

This specification closes the synchronous shared-state query defect formerly
marked in `Lambda64/gui/compositor.lisp` at `get-window-by-kind`.

## Required behavior

`get-window-by-kind` must not traverse `*window-list*` on its caller's thread.
It submits a query event and immediately returns a fresh result mailbox. The
compositor processes the query in FIFO order with window creation, closure, and
z-order events, then sends exactly one value to that mailbox: the frontmost
matching window, or `NIL` when no matching window exists. The reply send must be
nonblocking so an invalid consumer cannot stall the compositor event loop.

Internal compositor-only checks may use a private direct lookup while already
running on the compositor thread. In particular, screensaver state checks must
not enqueue a query that the same compositor thread would then need to service.
Existing synchronous consumers must receive from the returned mailbox before
branching on the result; they must not treat the mailbox itself as a window.

## Acceptance evidence

`Lambda64/tests/host/test-compositor-async-window-query.sh` must prove that the
public call does not inspect window state before event processing, returns an
empty fresh result mailbox, observes prior compositor events in FIFO order,
returns the frontmost match, delivers a valid `NIL` miss exactly once, and uses
a nonblocking reply. It must use the actual compositor create and close event
handlers to cover create-before-query, query-before-close, close-before-query,
and z-order semantics, and must execute the MED editor hook against both found
and missing results. The focused host test, `make test-fast`, and a guest test
covering the real compositor/mailbox scheduler are required before this item
may be marked verified.
