# TF-WI-0160: HTTP demo pending-connection cancellation contract

## Scope

`stop-server` must terminate accepted HTTP connections that are waiting for a
request, rather than waiting indefinitely for their dispatch work to finish.
The listener cancellation path and explicit server shutdown path both abort a
snapshot of tracked streams. Connection bookkeeping is protected by a mutex,
and each dispatched request removes its stream in `unwind-protect` so normal
completion and errors cannot leak entries.

## Required behavior

- Register an accepted stream before dispatching its request handler.
- On shutdown, close every currently tracked stream with `:abort t` outside the
  bookkeeping lock, waking a handler blocked in `read-line`.
- Untrack each stream in an `unwind-protect`, including request errors and
  abort-induced conditions.
- Preserve the existing listener cancellation, shutdown-group wait, and HTTP
  response behavior.

## Test-before evidence

Before implementation, the focused contract test failed because the source
still contained the baseline `Make pending connections cancellable` TODO and
had no tracked-connection cleanup path.

## Acceptance evidence

`Lambda64/tests/host/test-net-http-pending-cancellation.sh` checks the tracking,
abort, and unwind-protect contract and rejects a mutation that removes the
untracking call. `bash -n` and `make lisp-style-check` pass for the focused
change. Guest and integration-level evidence still require a running network
image and remain outstanding for this high-risk networking item.
