# TF-WI-0435: XP output-position fallback

## Scope

`Lambda64/system/xp.lisp` initializes the pretty-printer's `charpos` from
`stream-line-column`. Gray streams are allowed to return `nil` when the
column cannot be determined. The old code interpreted that value as column
zero, causing `fresh-line` decisions to suppress separators (notably in
backtraces).

## Contract

- Preserve a reported integer output column, including zero.
- Treat an unavailable/non-integer column conservatively as a non-zero
  position so XP does not assume it is already at the start of a line.
- Keep this behavior local to XP initialization; stream implementations and
  their existing `nil` contract are unchanged.

## Verification

- Host regression: `Lambda64/tests/host/test-system-xp-output-position.sh`
  checks the fallback and rejects a mutation that restores the old behavior.
