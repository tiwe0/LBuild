# TF-WI-0063: no-return call control-flow boundary

## Scope

`Lambda64/compiler/simplify-control-flow.lisp` simplifies terminating AST
forms but does not yet classify calls to no-return functions.

## Current boundary

A call is considered terminating only when an earlier child expression proves
control termination. Treating arbitrary calls as no-return requires reliable
function-effect metadata, including local declarations, unknown callees, and
multiple-value contexts; the marker remains active until that metadata contract
is implemented.

## Required evidence

Add compiler and host tests for declared no-return functions, unknown calls,
cleanup forms, and calls in argument lists before removing the marker.

## Implementation gate (2026-09-01)

This work item remains **active**. `simplify-control-flow-1` may only infer
termination from child expressions today; calls have no trusted no-return
metadata. Treating unknown or declared callees as terminating without the
specified effect contract could remove reachable cleanup or argument
expressions, so the marker and TODO must remain until host, codegen, and
cold-image tests are present.
