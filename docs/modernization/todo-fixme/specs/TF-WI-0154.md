# TF-WI-0154: Virgl command-buffer DMA reuse contract

## Scope

This specification closes the DMA reuse requirement in
`Lambda64/gui/virgl/virgl.lisp` for reset and re-finalization of an existing
command buffer.

## Required behavior

Finalization may reuse the existing DMA buffer only when it has not expired and
its capacity is at least the new submit request length. The current request
length is tracked separately from allocation capacity, so a shorter rebuilt
command submits only its header and payload rather than exposing the unused
tail. Reused storage must receive a newly encoded header, size, reserved fields,
and complete command stream; stale bytes from the previous finalization must
not be submitted.

Once a command buffer owns DMA storage, a later finalization continues using
the DMA path even when `:optimize` is omitted. This prevents reset followed by
ordinary finalization from submitting stale optimized storage. If the command
length changes or the buffer has expired, replacement storage must be allocated
before the old storage is released. Allocation failure therefore leaves the
previous slot and allocation intact rather than first destroying the only
valid storage.

Destroying a command buffer releases its DMA buffer and clears the slot, making
repeated destruction safe. Small command buffers that have never requested
optimization retain the existing copying submit path and do not allocate DMA.

## Test-before evidence

Before implementation, the source always allocated a new contiguous DMA buffer
on every optimized finalization and carried an explicit FIXME requesting
same-size reuse. Reset followed by a non-optimized re-finalization could also
leave an old DMA image selected. The initial focused test run exited nonzero
because the required reuse implementation was absent.

## Acceptance evidence

`Lambda64/tests/host/test-virgl-command-buffer.sh` resets and rebuilds a command
buffer with equal, smaller, and larger request sizes. It proves object identity
and a single allocation while capacity suffices, proves that the shorter
request length clips SG submission, proves replacement plus release only when
growth exceeds capacity, and validates that the replacement contains the new
command stream. An injected replacement-allocation failure proves that the old
slot remains live. The test also rejects reuse of an expired buffer, checks
release plus slot clearing during destruction, and proves that a small,
never-optimized command remains on the copying path.

Guest execution is still required by the ledger. No image-level repeated-submit
or reset/re-finalize run has been recorded, so the item remains active.
