# TF-WI-0366: ARM64 load-register-literal width and SIMD/FP decoding

## Scope

Close the literal-load FIXME in `Lambda64/system/disassemble-arm64.lisp`.
`LDR (literal)` must decode W and X destinations, `LDRSW (literal)` as an X
destination with its dedicated opcode, and SIMD/FP literals as S, D, or Q
registers according to `V` and `opc`.

## Required behavior

The signed `imm19` remains a PC-relative byte displacement (`imm19 << 2`).
For integer forms (`V=0`), `opc=0/1/2` select `LDR Wt`, `LDR Xt`, and
`LDRSW Xt`; reserved `opc=3` is rejected. For SIMD/FP forms (`V=1`),
`opc=0/1/2` select `LDR St`, `LDR Dt`, and `LDR Qt`; `opc=3` is rejected.

## Acceptance evidence

`Lambda64/tests/host/test-system-disassemble-arm64-literal.sh` checks the
source-level decode contract and runs a mutation-aware guard that replaces the
32-bit decoder with the former all-X behavior; the mutation must fail. This is
host fixture evidence; cold-image/integration execution remains a downstream
requirement of the work-item matrix.
