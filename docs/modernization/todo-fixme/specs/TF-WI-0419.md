# TF-WI-0419 — `MERGE` vector fast path

- **Code source of truth:** `Lambda64/system/sequence.lisp:1233-1270`
- **Risk:** medium
- **Required test levels:** host, cold-image, integration

## Objective

When `MERGE` receives vector sequences, consume those vectors directly rather
than routing them through `COERCE` and potentially allocating a copy. Non-vector
sequences retain the existing coercion path. This is behavior-equivalent because
`MERGE` only reads its inputs through `LENGTH`, `AREF`, and `SVREF`; the result
allocation and predicate/key invocation order are unchanged.

## Focused evidence

```sh
bash -n Lambda64/tests/host/test-system-sequence-merge-vector-fast-path.sh
bash Lambda64/tests/host/test-system-sequence-merge-vector-fast-path.sh
```

The host contract checks both vector branches and rejects a mutation that removes
the direct-vector guards. Cold-image and QEMU integration remain pending.
