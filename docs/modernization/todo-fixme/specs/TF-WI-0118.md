# TF-WI-0118: OHCI done queue completion order

## Scope

This specification closes the corresponding baseline marker formerly present
in `Lambda64/drivers/usb/ohci.lisp` while preserving the existing OHCI endpoint
and USB-driver callback interfaces.

## Required behavior

The writeback-done handler captures the hardware newest-first TD chain, reverses it, and dispatches oldest-first. Each TD callback or unsupported isochronous error is isolated and recorded, later captured TDs still run, and WD is acknowledged and re-enabled only after the whole captured list is attempted. Failure while capturing the list leaves WD unacknowledged for retry.

## Acceptance evidence

`Lambda64/tests/host/test-drivers-usb-ohci-semantics.sh` extracts and executes
the production OHCI forms under SBCL with mocked registers, DMA barriers, physical
address mappings, semaphores, and callbacks. It exercises SOF polling, all four
receive/send control timeout stages (including immediate and late reclamation and
stale-credit isolation), bulk dequeue, interrupt/bulk halt recovery, callback and
isochronous done-list error ordering, and periodic add/remove symmetry. A
mutation-negative assertion rejects ACK-before-dispatch ordering. The production
integration regexes are supplemental wiring checks rather than the behavioral
oracle. The pre-fix fixture failed with `Missing OHCI form: (defstruct
(control-completion`; the implemented source prints `OHCI production semantics
passed` and `OHCI source integration contract passed`.

The work item also requires `hardware-usb-ohci`. No physical OHCI controller or
OHCI-enabled guest was available for this pass, so DMA ordering, real interrupt
timing, device error recovery, cancellation under load, and controller-specific
behavior remain unverified. The specification therefore remains `active`.
