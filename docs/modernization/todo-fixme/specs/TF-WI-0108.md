# TF-WI-0108: Non-contiguous TD buffer identity

## Scope

This specification closes the corresponding baseline marker formerly present
in `Lambda64/drivers/usb/ohci.lisp` while preserving the existing OHCI endpoint
and USB-driver callback interfaces.

## Required behavior

`td-buf-info` receives the original Lisp buffer explicitly and returns it with the transfer count, because OHCI discards the first physical-page address after advancing CBP into a non-contiguous final page.

## Acceptance evidence

`Lambda64/tests/host/test-drivers-usb-ohci-semantics.sh` extracts and executes
the production OHCI forms under SBCL with mocked registers, DMA barriers, physical
address mappings, semaphores, and callbacks. It directly exercises two-page
transfer accounting and buffer identity, SOF polling, all four control timeout
stages, bulk dequeue, interrupt/bulk recovery, the writeback-done handler, and
periodic endpoint add/remove accounting. Production integration regexes are only
supplemental wiring checks. The pre-fix fixture failed with `Missing OHCI form:
(defstruct (control-completion`; the implemented source prints `OHCI production
semantics passed` and `OHCI source integration contract passed`, and its
ACK-before-dispatch source mutation is rejected.

The work item also requires `hardware-usb-ohci`. No physical OHCI controller or
OHCI-enabled guest was available for this pass, so DMA ordering, real interrupt
timing, device error recovery, cancellation under load, and controller-specific
behavior remain unverified. The specification therefore remains `active`.
