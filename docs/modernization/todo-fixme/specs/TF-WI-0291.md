# TF-WI-0291 — virtio-block `FLUSH` 请求

- **基线标记：** `TF-occ-87b29e289ffe77c202392765`
- **代码事实源：** `Lambda64/supervisor/virtio-block.lisp:100-149`
- **风险：** critical
- **要求测试层：** host、cold-image、integration

## 目标

`virtio-block-flush` 不得无条件返回成功；它要向 virtio-block 设备提交
`VIRTIO_BLK_T_FLUSH` 请求。请求只包含 16 字节 header 和 1 字节 status descriptor，
完成后释放 descriptor，并把设备状态映射为 `:no-error`、`:io-error`、`:unsupported`
或 `:unknown`。

## 先测试证据

新增 `Lambda64/tests/host/test-supervisor-virtio-block-flush.sh`，用最小 virtqueue/device
fixture 验证 request type、两段 descriptor 链、queue 0、完成状态和资源回收。

实现前运行：

```sh
bash Lambda64/tests/host/test-supervisor-virtio-block-flush.sh
```

旧实现仅返回 `t`，因此无法提交请求。变异负例把 FLUSH type 改为读请求，必须被测试拒绝。

## 验收标准

1. flush 使用 `VIRTIO_BLK_T_FLUSH`（值 4），不附带数据 descriptor。
2. header -> status descriptor，提交 queue 0，完成后释放两个 descriptor。
3. success、I/O error、unsupported、unknown status 正确映射。
4. IRQ latch 清理，不改变既有 read/write 路径。
5. cold image/QEMU integration 待完整环境验收，保持 `active`。
