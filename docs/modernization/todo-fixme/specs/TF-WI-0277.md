# TF-WI-0277: Large wired-backing allocation contract

## Scope

This item reduces physical allocator pressure when initializing snapshot backing
for dense wired ranges.

## Required behavior

Each 2 MiB-aligned virtual chunk is examined independently. If all 512 4 KiB
pages are present, the snapshotter first requests one contiguous 512-frame buddy
allocation and installs every backing-frame association. Partial, sparse, or
unavailable large runs fall back to mandatory single-page allocations.

## Test-before evidence

The focused test reported the former 2 MiB TODO; initialization always issued
one physical allocation per 4 KiB page.

## Acceptance evidence

The executable host regression supplies a complete aligned 512-page run and
verifies one large allocation plus first/last frame association. It also
extracts and executes production `ALLOCATE-SNAPSHOT-WIRED-BACKING-PAGES`, forces
the 512-frame request to fail, and verifies that all 512 mandatory single-page
fallback allocations and associations occur. This rejects disabling the dense
failure fallback. Physical buddy behavior still requires guest memory-pressure
testing.
