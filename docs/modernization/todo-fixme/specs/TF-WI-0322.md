# TF-WI-0322 — 字符名称修饰前缀的任意顺序解析

- **基线标记：** `TF-occ-5baf1ff2ac5488a662daa0f5`
- **代码事实源：** `Lambda64/system/character.lisp:500`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`name-char` 必须识别 `C-`、`M-`、`S-` 与 `H-` 四种修饰前缀的任意排列，而不是只
接受固定的 `C-M-S-H-` 顺序。每种修饰只能出现一次；没有修饰的名字、固定顺序的既有
名字、单字符名字及普通 Unicode/name 查找路径必须保持不变。

## 先测试证据

新增 `Lambda64/tests/host/test-system-character-prefix-order.sh`。测试从生产源提取实际
`name-char` 定义，并以最小字符名表验证全部 24 种前缀排列、未修饰路径、固定顺序、
重复前缀和仅前缀的边界。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-character-prefix-order.sh
```

失败并报告 `C-M-H-S-A` 未保留修饰位，证明原代码仅按固定顺序消费前缀。

## 验收标准

1. `C-`、`M-`、`S-`、`H-` 的每一种排列均产生相同四个修饰位。
2. 未修饰与原有 canonical `C-M-S-H-` 名称的结果保持兼容。
3. 重复修饰前缀和没有基字符的前缀输入返回 `nil`，不会被误解析为字符名。
4. host 测试直接加载生产定义，并以禁用前缀解析循环的变异负例锁定新路径；cold image
   与 QEMU integration 在后续完整测试阶段补齐。

## 当前证据

