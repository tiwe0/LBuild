# TF-WI-0047 — cross-compiler macrolet environment

- **Baseline marker:** `TF-occ-c53f4271b10af8c347efa2c7`
- **Code source of truth:** `Lambda64/compiler/cross-compile.lisp:442`
- **Risk:** critical
- **Required test levels:** host, codegen, cold-image

## Current boundary

`cross-support:x-eval` evaluates forms in the host Lisp, but currently ignores
the lexical environment argument.  The TODO records the missing bridge for
forms that depend on local `macrolet`/`symbol-macrolet` definitions.  Applying
ad-hoc host `macrolet`s would be unsound unless bindings are expanded in the
same order and with the same compiler-macro hooks as the target compiler.

## Required completion evidence

1. Specify a deterministic translation from the target lexical environment to
   host macrolet and symbol-macrolet bindings, including shadowing rules.
2. Add a focused host test covering nested macrolets and a mutation case where
   expansion outside the environment produces a different form.
3. Verify the resulting expansion at codegen and cold-image levels.

The marker remains `active` until this contract is implemented and tested;
removing it by merely ignoring `env` would hide a semantic loss.
