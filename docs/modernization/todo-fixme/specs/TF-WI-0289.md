# TF-WI-0289: thread final cleanup lock ordering boundary

`thread-final-cleanup` publishes the join event before acquiring the global
thread lock because `event-state` requires the lock to be released. The small
SMP visibility window is documented and intentionally retained until event
state publication and scheduler lock ordering can be redesigned together.

## Lock-order evidence

The current wake-up path has the lock order
`*big-wait-for-objects-lock* -> wait-queue lock -> wake-thread -> global
thread lock`. `event-state` drains wait queues while holding the first two
locks, and `wake-thread` acquires the global thread lock. Acquiring the global
thread lock before publishing the join event would invert this order and can
deadlock on SMP. A safe redesign must either defer wake-ups until all queue
locks are released or provide an explicit lock-held wake helper; changing only
`thread-final-cleanup` is insufficient.
