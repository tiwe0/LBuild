# TF-WI-0153: Virgl command-buffer scatter/gather submission contract

## Scope

This specification closes the command-buffer scatter/gather requirement in
`Lambda64/gui/virgl/virgl.lisp`. It applies to optimized command buffers and
buffers larger than the copying limit of `gpu:virtio-gpu-submit-3d`.

## Required behavior

A DMA-backed submit is one `VIRTIO_GPU_CMD_SUBMIT_3D` request. Its byte layout
is the 24-byte virtio-gpu control header, a 32-bit command-stream length, a
zero 32-bit reserved word, and the virgl command stream beginning at byte 32.
The request descriptor lengths together must cover exactly those bytes; page
rounding in the DMA allocator must not expose bytes beyond the request.

The DMA allocation is allowed to be physically discontiguous. Submission must
obtain every physical extent through `sup:dma-buffer-sg-entry` and create a
virtqueue descriptor for each extent needed by the current request. Capacity
beyond the request length must not add a zero-length descriptor. Each request
descriptor is device-read only and chains to the next descriptor. The final
request descriptor chains to one device-writable response descriptor backed by
the virtio-gpu driver's fixed response area.

The virgl lock remains outermost and the virtio-gpu command lock serializes the
queue and shared response area with the existing copying submission path. The
DMA cache is flushed before publishing the descriptor head. The producer waits
for the used index to advance before reading the response and releasing every
reserved descriptor.

If the queue cannot supply the complete chain, no partial chain may be
published, every descriptor already reserved must be returned, and submission
must enter the normal virgl command-error path. This implementation uses direct
virtqueue descriptors rather than the optional indirect-descriptor facility;
the supported SG count is therefore bounded by the currently available control
queue descriptors. Exceeding that bound fails explicitly and safely.

## Test-before evidence

`Lambda64/tests/host/test-virgl-command-buffer.sh` was first run against the
pre-change source. It exited with status 1 because the DMA request-prefix and
SG submission implementation did not exist. The pre-change submit branch also
unconditionally signalled `error "TODO"` whenever finalization selected DMA.

## Acceptance evidence

The focused host test executes the real finalization and DMA submission forms
against an instrumented virtqueue and a deliberately discontiguous DMA buffer.
It checks the byte layout, exact aggregate request length, descriptor addresses,
NEXT and WRITE flags, response chaining, cache-flush range, queue publication,
completion wait, descriptor release, response-error propagation, and partial
allocation cleanup. For every request descriptor, the expected address comes
directly from the corresponding DMA SG entry and the expected length is
`min(remaining request bytes, extent length)`; every NEXT pointer is compared
with the actual following descriptor. The response descriptor is required to
use exactly `request-phys + 2048`, length 24, WRITE-only flags, and a zero NEXT
field. A shorter request reusing a larger DMA allocation repeats the same
per-descriptor checks and proves the final SG extent is clipped to the current
request length. The ordinary small-buffer copying path is also retained.

The ledger requires a guest test. The host adapter does not execute a real
virtio-gpu device or virgl renderer, so this item must remain active until an
image-level optimized command-buffer submission succeeds on the guest and its
rendered result is observed.
