# TF-WI-0470: Define rw-lock contested handoff boundary

## Scope

Close the lock optimization TODO in `Lambda64/supervisor/sync.lisp`.

## Contract

`rw-lock-release-slow` keeps write-contested mode while handing ownership to a
waiting writer. Detecting that the writer is the only waiter requires an atomic
observation of both wait queues and the reader count; relaxing the mode without
that snapshot could race a concurrent acquirer and violate writer preference.
Any optimization must introduce an explicit atomic state protocol first.

## Verification

`Lambda64/tests/host/test-supervisor-sync-rw-lock-handoff-contract.sh` checks
marker removal and preservation of the contested-handoff safety rationale.
