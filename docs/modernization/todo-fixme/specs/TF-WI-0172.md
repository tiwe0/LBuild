# TF-WI-0172: Wired symbol-name ownership contract

## Scope

This contract resolves the corresponding baseline directive in
`Lambda64/runtime/allocate.lisp` without changing its public allocator API.

## Required behavior

`make-symbol` copies the supplied character sequence into the wired area before storing it. The exact code-point sequence is preserved because Common Lisp symbol identity is defined by the supplied name; silently applying Unicode canonical equivalence would merge otherwise distinct names.

## Test-before evidence

The strengthened production-direct fixture initially failed because it expected
the old constant mock object rather than executing the object returned by the
real `make-symbol` path. The fixture now follows the returned object and would
fail if the production copy were replaced by a constant string.

## Acceptance evidence

The production-direct fixture executes both `copy-symbol-name-to-wired-area`
and `make-symbol`. It supplies canonically equivalent but distinct precomposed
and decomposed non-ASCII names, then proves each full code-point sequence is
copied to distinct wired storage without normalization. A targeted
constant-`"alpha"` mutation must fail the fixture.

The focused fixture extracts and executes production forms while replacing only
Mezzano memory, tag, and atomic primitives with deterministic host facades. It
also rejects any remaining TODO/FIXME marker in the owned production file.

Cold-image boot, concurrent SMP allocation, pager fault handling, and long-run
GC behavior have not been exercised by this host run. This item remains active
until those integration requirements are verified in a guest image.
