# TF-WI-0423 — 与字符串存储宽度无关的哈希

- **基线标记：** `TF-occ-a73665e67d2448d7b25d23a9`
- **代码事实源：** `Lambda64/system/string.lisp:147`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`hash-string` 必须只依赖字符串的逻辑字符序列。同一组字符即使分别由 8、16 或
32 位简单字符串存储，或由 displaced string 表示，也必须产生相同哈希；字符
码点不同的部分仍参与哈希。

实现统一使用原先 displaced-string 路径的 32 位受限 DJB2 计算，保留字符的
Unicode 码点与 Mezzano character bits，不再将底层存储字直接混入结果。

## 先测试证据

新增 `Lambda64/tests/host/test-system-string-hash-encodings.sh`。测试从生产源
提取实际 `hash-string` 定义，对同一 ASCII、Unicode 和组合字符字符串模拟
narrow、wide、fullwidth backing storage，同时保留一个无 backing-storage 的
回退表示。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-string-hash-encodings.sh
```

空字符串的四个表示得到不同值（例如模拟 narrow/wide/fullwidth 分别为
`#x11111111`、`#x22222222`、`#x33333333`，回退值为 `5381`），从而失败。

## 验收标准

1. 相同逻辑字符序列在所有简单字符串存储宽度和 displaced 表示下得到相同值。
2. 哈希等于逐字符 `char-int` 的 32 位 DJB2 结果，因而 Unicode 码点与 character
   bits 均参与计算。
3. 哈希实现不再读取 simple-string 的原始 numeric backing storage。
4. host 测试直接加载生产定义，并以将字符码点项置零的变异负例锁定行为；
   cold image 与 QEMU integration 在后续完整测试阶段补齐。

## 当前证据
