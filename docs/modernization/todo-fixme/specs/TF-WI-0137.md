# TF-WI-0137: Local pathname wildcard-string contract

## Scope

This specification closes the wildcard-string requirement formerly recorded at
`Lambda64/file/local.lisp:556`. It applies to local `DIRECTORY` traversal and
does not alter exact pathname lookup used by `OPEN`, `PROBE-FILE`, or
`TRUENAME`.

## Required behavior

- A `*` embedded in a string directory, name, or type component matches zero or
  more characters. Matching remains case-insensitive, consistent with the
  local directory name table's `EQUALP` comparison.
- Multiple and trailing `*` characters work without treating adjacent literal
  characters as optional. A string without `*` remains an exact,
  case-insensitive match.
- `:WILD` continues to match a complete component, and exact directory
  pathnames retain their prior behavior.
- A wildcard string selects only matching subdirectories or file entries; it
  must not broaden a query to unrelated siblings.
- A directory-only wildcard query returns one canonical pathname for each
  actual matching directory. Returned directory components contain no
  wildcard markers, and `NAME` and `TYPE` are `NIL`; the original query
  pathname must not be returned in place of its matches.

## Test-before evidence

Before implementation,
`bash Lambda64/tests/host/test-file-local-semantics.sh` failed with
`Wildcard string directory/name/type matching failed`, returning no matches for
the `src*` / `a*` / `li*` query.

A review regression added before the directory-result fix failed with
`Directory-only wildcard-string matching`: expected the distinct canonical
directories `(:ABSOLUTE "src")` and `(:ABSOLUTE "src-old")`, but received the
single original query directory `(:ABSOLUTE "src*")`.

## Acceptance evidence

`Lambda64/tests/host/test-file-local-semantics.sh` directly extracts the
production matching functions and covers wildcard strings in directory, name,
and type components alongside exact and `:WILD` traversal. It also asserts
that a directory-only `src*` query preserves both actual matches as canonical
directory pathnames. The focused host test must pass.

The work item remains active until a booted Lambda64 guest and integration run
exercise the same `DIRECTORY` queries on `LOCAL:` as required by the ledger.
