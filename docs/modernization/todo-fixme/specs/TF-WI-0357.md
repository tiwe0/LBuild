# TF-WI-0357 — 宏定义文档字符串传播

- **基线标记：** `TF-occ-955c3ed996b451329344d02b`
- **代码事实源：** `Lambda64/system/defmacro.lisp:188-289`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`defmacro` 和 `define-compiler-macro` 在调用现有 `%defmacro` 与
`%define-compiler-macro` 存储接口时，必须传入由 `parse-declares` 识别的 docstring。
展开器仍负责从 macro body 去除文档字符串；局部 `macrolet` 不建立全局可检索文档，行为
不变。

## 先测试证据

新增 `Lambda64/tests/host/test-system-defmacro-documentation.sh`，它加载生产的 lambda-list
展开器及两个定义宏，并以最小文档存储替身执行实际宏展开。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-defmacro-documentation.sh
```

失败并报告：

```text
DEFMACRO docstring was not stored: NIL
```

说明虽然运行时存储接口支持 documentation，调用方没有传递它。回归同时覆盖
`define-compiler-macro` 的独立存储路径；变异负例将两个传参置为 `nil`，必须被拒绝。

## 验收标准

1. `defmacro` 的第一条 body 字符串保存为 function documentation。
2. `define-compiler-macro` 的第一条 body 字符串保存为 compiler-macro documentation。
3. 文档字符串不成为宏函数运行时 body 的可执行 form。
4. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。

## 当前证据

```sh
bash -n Lambda64/tests/host/test-system-defmacro-documentation.sh
bash Lambda64/tests/host/test-system-defmacro-documentation.sh
```

两项均已通过；后者同时确认置空 documentation 参数的变异被拒绝。尚未执行 cold image
或 QEMU integration，故本工作项保持 `active`。
