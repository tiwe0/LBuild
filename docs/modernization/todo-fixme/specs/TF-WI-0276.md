# TF-WI-0276: Snapshot completion sleep handoff contract

## Scope

This item closes the wakeup race between completion signalling and the snapshot
thread entering sleep.

## Required behavior

With interrupts disabled and the global thread lock held, the snapshot thread
first publishes its `:SLEEPING` state and wait item, then clears
`*SNAPSHOT-IN-PROGRESS*` as the final store. A requester cannot win the CAS until
the target is already wakeable. Completion and epoch events remain signalled
before this handoff.

## Test-before evidence

The focused test reported the original race marker. Previously the in-progress
flag was cleared before the thread state became sleeping.

## Acceptance evidence

The host contract checks the production store order and executes the sleep
state helper. A high-contention multi-CPU guest loop is required to prove no
lost wakeups under real scheduler interleavings.
