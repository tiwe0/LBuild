# TF-WI-0255: DMA allocation pager reclaim policy

## Scope

The physical allocator currently exposes no pager-reclaim hook. A failed DMA
allocation therefore remains non-blocking and does not attempt an invented
pager call. The source TODO is intentionally retained until that integration
exists.

## Verification boundary

The host contract test confirms the TODO and the existing `ERRORP`/NIL behavior.
Guest or hardware integration is required before a reclaim policy can be
implemented safely.

# TF-WI-0255: Define DMA buffer allocation failure boundary

## Scope

Close the pager-reclaim TODO in `Lambda64/supervisor/dma-buffer.lisp`.

## Contract

When transient physical allocation fails, DMA buffer creation remains
non-blocking and returns `nil` (or signals `dma-buffer-allocation-error` when
requested). The physical allocator has no pager-reclaim hook; attempting an
ad-hoc page-in/reclaim from this path would violate the pager ABI and can deadlock
allocation. A future reclaim integration must be introduced through an explicit
allocator hook and timeout policy.

## Verification

`Lambda64/tests/host/test-supervisor-dma-buffer-allocation-contract.sh` checks
marker removal and preservation of the non-blocking failure contract.
