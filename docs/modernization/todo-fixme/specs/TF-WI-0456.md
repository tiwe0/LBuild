# TF-WI-0456 — x86-64 direct/indirect RIP call annotation

## Scope

Close the annotation TODO at `Lambda64/system/disassemble-x86-64.lisp:53`.
The `E8`/`E9` relative control-flow operand is a direct code target; the
`FF /2` or `FF /4` RIP-based effective address is an indirect memory operand
whose contents hold the target. The printer must not dereference a direct code
target as if it were an object pointer.

## Invariants

- Relative `call`/`jmp` decoding marks its RIP operand as a direct target.
- RIP-relative effective-address calls/jumps decoded through `FF` remain
  indirect and retain object-pointer annotation behavior.
- The distinction is metadata on the instruction, not a heuristic based only
  on `ea-base`, since both encodings expose `:rip` effective addresses.

## Acceptance evidence

`Lambda64/tests/host/test-system-disassemble-rip-call.sh` checks that the
instruction metadata, relative decoder marking, and printer guard are present.
It mutates away the direct-target guard and requires the test to fail, guarding
against regression to unconditional RIP-memory dereference.

Full image/codegen integration remains dependent on the project build
environment.
