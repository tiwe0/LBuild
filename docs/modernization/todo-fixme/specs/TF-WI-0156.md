# TF-WI-0156: File-backed window-control image assets

## Scope

This work item moves the normal and hover window close-button pixels out of
`Lambda64/gui/widgets.lisp` and into deterministic PNG resources. It uses the
existing cold-image asset boundary rather than introducing a new loader:
`Lambda64/ipl.lisp` loads `gui/image.lisp`, copies every
`SYS:SOURCE;GUI;*.png` file to `LOCAL:>Icons>`, and only then loads
`gui/widgets.lisp`.

The editable source artwork remains `Lambda64/gui/close-button.psd`. Direct
exports of that layered 150x150 document with the locally available
ImageMagick and macOS `sips` renderers did not reproduce the two existing 14x14
runtime states: the PSD composite contains the hover X, has no separate
flattened normal state, and the renderers' resized alpha/compositing output
differs from the production pixels. The PNGs are therefore lossless exports of
the two previously embedded arrays, preserving the exact existing normal and
hover appearance rather than substituting a newly rendered design.

## Required behavior

- `*close-button*` loads `LOCAL:>Icons>close-button.png` through
  `mezzano.gui.image:load-image`.
- `*close-button-hover*` loads
  `LOCAL:>Icons>close-button-hover.png` through the same established loader.
- Both resources are non-interlaced 14x14, 8-bit RGBA PNGs.
- Decoding the PNGs produces exactly the same RGBA pixels as the former Lisp
  arrays. In particular, transparent RGB values are retained rather than
  normalized, so blending and alpha hit-testing remain unchanged.
- No network service, new runtime package, fallback embedded copy, or lazy
  first-draw I/O is introduced. The resources are copied into the cold image
  before `widgets.lisp` is loaded.

## Test-before evidence

Before implementation, `Lambda64/tests/host/test-gui-widget-assets.sh` exited
with status 1:

```text
widget asset contract missing: normal close button is loaded from the image copied into LOCAL:>Icons>
```

The old implementation constructed both surfaces from large literal arrays in
`widgets.lisp` and contained no corresponding PNG resources.

## Acceptance evidence

`Lambda64/tests/host/test-gui-widget-assets.sh` checks the real source and
resource files. It verifies both fixed `LOCAL:>Icons>` load paths, rejects a
remaining embedded pixel fallback or debt marker, decodes PNG scanlines using
the standard PNG filters, checks the format and dimensions, and compares each
decoded RGBA stream with the SHA-256 digest of its legacy pixel array. It also
checks the cold-image ordering and wildcard-copy boundary in `ipl.lisp`.

The focused host test, shell syntax check, documentation validation, Lisp style
check, and diff whitespace check are required evidence for this slice. A guest
boot should additionally confirm that normal and hover rendering and alpha
hit-testing are unchanged. No guest execution is recorded here, so this work
item must not yet be marked verified in the ledger.
