# TF-WI-0132: Non-terminal FROM wild-inferiors pathname contract

## Scope

This specification replaces the former restriction at
`Lambda64/file/fs.lisp:624` that required `:WILD-INFERIORS` to be the final
`FROM-WILDCARD` directory element. It covers directory validation performed by
`PATHNAME-MATCH-P` and capture performed by `TRANSLATE-PATHNAME`.

## Required behavior

- `:WILD-INFERIORS` matches zero or more directory components and then resumes
  matching all following pattern components.
- A suffix after `:WILD-INFERIORS` is mandatory when present. A source with a
  different or missing suffix does not match and cannot be translated.
- Translation captures only the directory components consumed by
  `:WILD-INFERIORS`; the matched suffix is not copied as part of that capture.
- Zero-level matches produce an empty capture.
- `:WILD` in a directory pattern consumes exactly one component, including
  when used in a suffix after `:WILD-INFERIORS`.
- `TRANSLATE-PATHNAME` validates the complete pathname against
  `FROM-WILDCARD`, including host, device, directory, name, type, and version,
  before constructing a result.
- A `NIL` source and `FROM-WILDCARD` directory still applies the declared
  literal `TO-WILDCARD` directory; absence of a FROM directory does not replace
  or suppress the destination directory.

These rules implement the Common Lisp requirement that
`(PATHNAME-MATCH-P source from-wildcard)` be true before translation and the
standard meaning of `:WILD-INFERIORS` as any number of directory levels.

## Test-before evidence

Before implementation,
`FILE_FS_CASE=0132 bash Lambda64/tests/host/test-file-fs-semantics.sh` failed
with `A non-terminal :WILD-INFERIORS pattern ignored a mismatched suffix`.
The previous matcher returned true immediately upon encountering
`:WILD-INFERIORS`, so it never validated the remaining `"leaf"` component; the
translation path also retained an assertion that the wildcard must be last.

A second test-before check then failed with `TRANSLATE-PATHNAME ignored a
FROM-WILDCARD host mismatch`, proving that directory-only validation was not
sufficient for the complete pathname contract.

The independent review regression for a `NIL` source/FROM directory then
failed with `A NIL FROM directory ignored the literal TO directory`, returning
`NIL` instead of `(:ABSOLUTE "literal")`.

## Acceptance evidence

`Lambda64/tests/host/test-file-fs-semantics.sh` extracts the production matcher
and translator. It covers a multi-level capture, an empty capture, suffix
mismatch rejection, and translation failure when the source does not match the
full `FROM-WILDCARD`, including a mismatched host.
It also verifies that a literal TO directory is retained when both source and
FROM directory components are `NIL`.

The work item remains active until equivalent logical and physical pathname
cases run in a booted Lambda64 guest and integration environment.
