# TF-WI-0476: Define virtio GPU framebuffer contiguity boundary

## Scope

Close the discontiguous-framebuffer TODO in
`Lambda64/supervisor/virtio-gpu.lisp` without changing the framebuffer ABI.

## Contract

The current `RESOURCE_ATTACH_BACKING` command emits one backing entry
(`nr-entries = 1`), and `video-set-framebuffer` publishes one physical base.
The DMA allocation therefore remains explicitly contiguous. Supporting a
discontiguous framebuffer requires a variable-entry command payload plus
scatter/gather scanout plumbing; it is not safe to infer from the existing
single-base API.

## Verification

`Lambda64/tests/host/test-supervisor-virtio-gpu-framebuffer-contract.sh` checks
that the TODO is closed while the one-entry, contiguous-allocation boundary
and its rationale remain present.
