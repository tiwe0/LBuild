# TF-WI-0279: SMP snapshot request claim contract

## Scope

This item serializes concurrent snapshot requests from multiple CPUs.

## Required behavior

`SNAPSHOT-CLAIM-REQUEST` uses CAS on the global in-progress cell. Only the CPU
that observes NIL may clear the completion event, publish the next epoch, and
wake the snapshot thread. Losing callers neither overwrite request state nor
issue another wake.

## Test-before evidence

The focused test reported the former SMP-locking marker; CAS existed inline but
its ownership boundary was not isolated or regression-tested with all associated
state updates.

## Acceptance evidence

The executable host regression makes two claims and verifies one winner, one
wake, and preservation of the first epoch. True simultaneous CAS contention
remains a multi-CPU guest stress test.
