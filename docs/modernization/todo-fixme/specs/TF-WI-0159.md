# TF-WI-0159: DNS resource-record packet encoding contract

## Scope

This specification closes the missing resource-record encoding path in
`Lambda64/net/dns.lisp`. `build-dns-packet` must build all four classic DNS
sections instead of accepting questions only. The record representation is the
same list representation returned by `decode-dns-packet`, so a decoded packet
can be encoded again without translating its records into another internal
format.

## Required behavior

The packet header must contain the actual question, answer, authority, and
additional record counts. A question is `(name type class)`. A resource record
is `(name type class ttl &rest data)`, with the following Internet-class RDATA
forms:

- `A` has one unsigned 32-bit IPv4 value;
- `AAAA` has one 16-octet vector;
- `CNAME`, `PTR`, `MB`, `MD`, `MF`, `MG`, `MR`, and `NS` have one domain name;
- `MX` has an unsigned 16-bit preference followed by one domain name;
- `SOA` has its two domain names followed by five unsigned 32-bit values;
- record types whose decoder exposes opaque RDATA have one octet vector.

Non-Internet classes also carry one opaque octet vector, matching the existing
decoder. Unknown types and classes use the decoder's
`(:unknown-type unsigned-16)` and `(:unknown-class unsigned-16)` forms and must
round-trip without losing their numeric codes.

Names are emitted uncompressed and lower-cased, preserving the pre-existing
question behavior. Every label is limited to 63 octets and the complete encoded
name, including label leaders and the root terminator, is limited to 255 octets.
The classic UDP packet buffer remains 512 octets. A record with the wrong RDATA
arity or width, an invalid scalar value, an overlong name, or a packet that
would exceed that buffer must signal rather than return truncated or corrupt
wire data.

## Test-before evidence

Before implementation,
`bash Lambda64/tests/host/test-net-dns-resource-records.sh` exited with status 1
at the original `TODO...` error as soon as the fixture supplied non-empty
answer, authority, and additional sections. The captured backtrace identified
`build-dns-packet` as the failing boundary.

## Acceptance evidence

`Lambda64/tests/host/test-net-dns-resource-records.sh` loads the real DNS packet
builder and decoder into a host facade. It constructs a packet containing every
section, typed `A`, `AAAA`, domain-name, `MX`, and `SOA` RDATA, opaque data, and
unknown type/class codes, then decodes the packet and compares every header and
record value. It also verifies missing and out-of-range `A` data, short `AAAA`
data, a packet of exactly 512 octets, rejection of the next octet, and rejection
of an encoded name longer than 255 octets.

The focused host test, Lisp style validation, and whitespace-clean diffs cover
the local implementation contract. The work-item ledger additionally requires
guest and integration evidence. No guest UDP exchange against an independent
DNS peer is recorded yet, so this item must remain active until image-level
network evidence verifies the emitted records on the wire.
