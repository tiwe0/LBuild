# TF-WI-0272: Snapshot CPU-quiescence contract

## Scope

This item makes the CPU-stability precondition of wired copying explicit.

## Required behavior

`CALL-WITH-SNAPSHOT-VM-STABLE` enters the existing world-stop primitive, whose
implementation quiesces every online CPU, before acquiring the VM write lock.
`SNAPSHOT-COPY-WIRED-AREA` rejects calls unless the world is stopped. Copying is
therefore performed only while other CPUs are quiescent and interrupts are
disabled locally.

## Test-before evidence

The focused test reported the former warning that world stop did not suspend
other CPUs; the current thread subsystem now includes CPU quiescence in
`CALL-WITH-WORLD-STOPPED`, but snapshot did not assert that dependency.

## Acceptance evidence

The host regression executes the orchestration helper and verifies world-stop
begins before VM locking and the critical copy phase. Multi-CPU guest stress is
still required to validate architecture IPI delivery.
