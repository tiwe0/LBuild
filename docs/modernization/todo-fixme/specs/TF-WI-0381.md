# TF-WI-0381: Lexical environment propagation during file compilation

## Scope

This work item makes the environment boundary in the compile-file read loop
explicit and closes the remaining lexical-environment hole in SETQ lowering.

## Required behavior

Each source form enters `handle-top-level-form` with the explicit null top-level
environment. That handler supplies environments extended by `LOCALLY`,
`MACROLET`, and `SYMBOL-MACROLET` to both compilation and compile-time
evaluation callbacks. SETQ tests symbol macros with `macroexpand-1` in that
active environment and lowers the expanded form, not the unexpanded source.

## Acceptance evidence

`Lambda64/tests/host/test-system-file-compiler-semantics.sh` constructs an
actual SBCL lexical environment containing a symbol macro, executes the
production SETQ lowering, and verifies that LLF commands reference the expanded
place rather than a global assignment to the symbol. It also checks the
explicit entry environment and macrolet evaluation environment. Replacing the
SETQ lookup environment with `NIL` is a required failing mutant. The pre-change
`HEAD` source fails with exit 1; the implemented source passes both semantic
and mutation-negative runs.

Full nested top-level forms compiled and loaded inside a cold guest remain an
integration gap, so this specification remains `active`.
