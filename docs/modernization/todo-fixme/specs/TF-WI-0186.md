# TF-WI-0186: Float to integer bignum construction boundary

The `%%truncate-*-float-to-integer` helpers currently decode IEEE bits and
construct the integer through ordinary Lisp arithmetic. Directly filling a
bignum would be an allocation and canonicalization optimization, not a
comment-only cleanup: sign, subnormal, overflow, and zero cases must remain
identical on all three float widths.

Required evidence: host cross-width bit-pattern tests and allocation/GC safety
coverage before replacing the existing arithmetic implementation.
