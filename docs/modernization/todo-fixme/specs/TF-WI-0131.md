# TF-WI-0131: FAT32 ensure-directories verbose contract

## Scope

This specification closes the ignored `verbose` argument in
`ensure-directories-exist-using-host` in `Lambda64/file/fat32.lisp`.

## Required behavior

- The method retains its boolean result: true when it creates at least one
  directory and false when the complete path already exists.
- With `verbose` true, each directory successfully created by the current call
  produces exactly one line on standard output. The line contains a directory
  pathname built from the original pathname defaults and the complete prefix
  through the newly created component.
- Existing parent directories do not produce creation lines. Repeating the
  operation on an existing path produces neither output nor a true creation
  result.
- Existing directory components are found with FAT's case-insensitive exact
  comparison. An asterisk in an ensure-directories component is a literal
  character here, not the directory-query wildcard used by `directory`.
- If an existing case-insensitive name match is an ordinary file rather than a
  directory, the operation signals `simple-file-error` before reading it as a
  directory. It neither creates a same-name directory nor emits verbose output.
- With `verbose` false or omitted, directory creation remains silent.

## Test-before evidence

Before implementation, the method explicitly declared `verbose` ignored. A
behavioral focused run created two missing nested directories but exited 1
because standard output remained empty.

## Acceptance evidence

`Lambda64/tests/host/test-file-fat32-verbose.sh` extracts the production method
and runs it against an in-memory directory-entry facade. It starts below an
existing parent requested with different letter case, creates two nested
directories, checks exactly two pathname reports, repeats the operation to
prove silent no-op behavior, and separately proves that `verbose nil` creates
silently. A same-name ordinary-file fixture must signal `simple-file-error`
without adding an entry or producing a creation report.

The focused host test passes. A writable guest FAT32 image creation run and the
required integration evidence remain outstanding, so this item stays active.
