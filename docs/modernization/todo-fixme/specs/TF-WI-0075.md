# TF-WI-0075: Intel GMA current interlace state

## Scope

This specification resolves the corresponding baseline marker in
`Lambda64/drivers/intel-gma.lisp` without expanding the supported PCI device
list or weakening modeset safety.

## Required behavior

Saved mode parameters decode the PIPECONF interlace field instead of always reporting a progressive mode. Mode programming writes progressive or field-indication scan mode from the timing object.

## Acceptance evidence

The focused host fixture loads the real register helpers and exercises timing validation; hardware readback remains required for PIPECONF state. `Lambda64/tests/host/test-intel-gma-timings.sh` loads the repository
driver with host MMIO stubs and executes its pure timing and register semantics.
Against the pre-change source, the fixture fails because the named sync
constructor and other required behavior are absent; against this implementation
it passes.

This work item remains `active` until a GMA 950 guest/hardware run records PLL
lock, two-frame shutdown, register readback, and stable physical scanout across
progressive/interlaced EDID modes. Host tests do not claim those electrical or
timing properties.
