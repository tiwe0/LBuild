# TF-WI-0139: Local soft-delete and expunge contract

## Scope

This specification separates logical deletion from physical removal for the
automatic-persistence-backed local filesystem.

## Required behavior

- `DELETE-FILE-USING-HOST` marks the selected version with the file property
  `:DELETED T`. A direct host call with version `:WILD` marks every version in
  the selected name/type container.
- Delete does not remove a directory entry or version object. Until expunged,
  the version remains addressable and visible to the existing local lookup and
  directory machinery.
- Deleting a nonexistent selection signals `SIMPLE-FILE-ERROR`; deleting a
  previously marked version is idempotent.
- `EXPUNGE-DIRECTORY-USING-HOST` physically removes marked entries from exactly
  the requested directory. It preserves unmarked versions and their order,
  removes an empty name/type container, and does not recursively alter child
  directories.
- Expunge mutates the directory table only after scanning it, avoiding hash
  table modification during `MAPHASH`.

## Test-before evidence

Before implementation,
`bash Lambda64/tests/host/test-file-local-semantics.sh` demonstrated that the
existing delete path physically removed the selected version immediately; the
local host also had no applicable expunge method.

## Acceptance evidence

`Lambda64/tests/host/test-file-local-semantics.sh` directly executes production
delete and expunge definitions. It covers a selected version, wildcard
selection, pre-expunge addressability, survivor order, empty-container removal,
and the missing-file error path. The focused host test must pass.

The work item remains active until guest and integration evidence confirms that
the `:DELETED` marker persists across Lambda64 runtime activity and that a real
`LOCAL:` expunge reclaims only marked entries.
