# TF-WI-0385: Floating-point FORMAT directives

## Scope

This specification closes the corresponding baseline marker formerly present
in `Lambda64/system/format.lisp` without narrowing Common Lisp `FORMAT`
argument-consumption or error behavior.

## Required behavior

The early formatter implements `~F`, `~E`, `~G`, and `~$`, including explicit precision and scale, field width, padding, overflow characters, exponent signs/digits, general-format selection, monetary minimum integer digits, and colon/at-sign sign placement. When `~F` precision is omitted, scale participates in choosing the default fractional precision. Fixed-form `~G` retains its decimal point after rounding to zero fractional digits, while exponential-form `~G` retains the requested significant precision. `~E` and exponential `~G` fill the field with the overflow character when the displayed exponent exceeds the explicit exponent-digit count, independently of the total rendered width. Non-real monetary arguments retain right-aligned field-width behavior. Decimal rounding is performed from the exact rational value of finite reals.

## Acceptance evidence

`Lambda64/tests/host/test-system-format-semantics.sh` loads the repository
implementation rather than the host `FORMAT` and covers scaled default `~F`
precision, exponent-digit overflow, monetary non-real width, and the
fixed/exponential `~G` rounding boundary, together with
cross-directive argument-pointer and nesting behavior. Against the
pre-change `HEAD` source, the focused command exits non-zero; its first failure
is grouped integer width (`"      1,234"` instead of `"     1,234"`). Against
the implemented source, the focused command passes.

The work item requires cold-image and integration levels in addition to the
host fixture. Guest execution against Mezzano streams and the late pretty
printer has not yet been recorded, so this specification remains `active`.
