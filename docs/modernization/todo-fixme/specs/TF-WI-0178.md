# TF-WI-0178: Atomic card dirty-generation update contract

## Scope

This contract resolves the corresponding baseline directive in
`Lambda64/runtime/allocate.lisp` without changing its public allocator API.

## Required behavior

Dirty-generation replacement remains one linearizable compare/exchange of the complete card word, preserving unrelated offset and flag fields. An idempotent fast path avoids a write when the requested generation is already present. Separate atomic AND then OR operations are deliberately not used because their interleaving can synthesize a generation no writer requested.

## Test-before evidence

An ordinary read/`dpb`/`setf` implementation passes single-thread value checks
but is not linearizable. The focused test therefore includes an explicit
mutation gate that replaces the helper with that implementation and requires
the test to fail because the production form no longer contains CAS. A second
counterexample retains CAS but attempts it only once; under an injected winning
competitor update it fails to install the requested generation.

## Acceptance evidence

The production-direct fixture updates the field inside a populated card word,
verifies the encoded generation and preservation of unrelated fields, then
verifies an idempotent repeat leaves the word unchanged. Its CAS facade then
injects a competing complete-word write immediately before the first exchange
and returns the conflicting word. The extracted production helper must reread,
complete on its second CAS, install the requested generation, and preserve all
unrelated bits from the competitor word. The no-CAS mutation rejects an
ordinary read/modify/write implementation, while the single-attempt-CAS
mutation proves that merely retaining one compare/exchange is insufficient.

The focused fixture extracts and executes production forms while replacing only
Mezzano memory, tag, and atomic primitives with deterministic host facades. It
also rejects any remaining TODO/FIXME marker in the owned production file.

Cold-image boot, concurrent SMP allocation, pager fault handling, and long-run
GC behavior have not been exercised by this host run. This item remains active
until those integration requirements are verified in a guest image.
