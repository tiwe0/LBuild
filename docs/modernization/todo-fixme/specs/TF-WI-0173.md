# TF-WI-0173: Wired function-area expansion contract

## Scope

This contract resolves the corresponding baseline directive in
`Lambda64/runtime/allocate.lisp` without changing its public allocator API.

## Required behavior

Wired function allocation can expand downward from `*wired-function-area-limit*`. A successful mapping publishes a new freelist entry, card offsets, bin membership, and the lower limit only after mapping succeeds.

## Test-before evidence

Before the mapping-result guard was covered directly, replacing it with an
unconditional success allowed publication after a rejected pager request. The
new mutation gate reproduces that counterexample and must fail.

## Acceptance evidence

The production-direct fixture executes `expand-function-area` itself for false,
exceptional, and successful pager results. False and exception paths preserve
the old wired limit and empty bins; success publishes the lower limit and new
freelist entry. It also executes `expand-allocation-area` with the same
false/exception/no-publication contract and with the young-generation ceiling.
An unconditional-mapping mutation must fail.

The focused fixture extracts and executes production forms while replacing only
Mezzano memory, tag, and atomic primitives with deterministic host facades. It
also rejects any remaining TODO/FIXME marker in the owned production file.

Cold-image boot, concurrent SMP allocation, pager fault handling, and long-run
GC behavior have not been exercised by this host run. This item remains active
until those integration requirements are verified in a guest image.
