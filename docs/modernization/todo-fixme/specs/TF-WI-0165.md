# TF-WI-0165: TCP reset sequence validation contract

## Required behavior

An RST in `:SYN-SENT` is accepted only when ACK is present and acknowledges
`SND.NXT`. In synchronized states its sequence must be acceptable in the receive
window, including 32-bit wraparound. Invalid synchronized resets leave state
unchanged and trigger a challenge ACK; invalid active-open resets are ignored.

## Evidence

The host regression executes production `ACCEPTABLE-SEGMENT-P`,
`TCP-RESET-ACCEPTABLE-P`, and `TCP4-CONNECTION-RECEIVE`. It covers a non-empty
segment whose first sequence is before the window but whose last byte overlaps
it (`50+60-1` against `[100,200)`), wrapping windows, and an out-of-window RST
that must preserve state and emit a challenge ACK. Removing the challenge is a
rejected mutant, as is an always-reject reset validator: normal and wrapping
valid resets must detach with `CONNECTION-RESET`. Wire interoperability remains
guest/network validation. `:SYN-SENT` is separately gated: an ACK-less or
wrong-ACK RST is rejected, while an ACK exactly matching `SND.NXT` is accepted;
an always-true validator mutant is rejected.
