# TF-WI-0130: FAT32 wildcard string matching contract

## Scope

This specification closes the wildcard-string requirement formerly located in
the exact-directory branch of `match-in-directory` in
`Lambda64/file/fat32.lisp`.

## Required behavior

- A `*` embedded anywhere in a string pathname component matches zero or more
  characters. Multiple stars and leading or trailing stars are supported.
- String matching is case-insensitive, preserving FAT lookup semantics. A
  string without `*` remains an exact case-insensitive component match, while
  the pathname marker `:wild` continues to match every component.
- The same component matcher applies to directory components, pathname names,
  and pathname types. `nil` name or type components retain exact `nil`
  semantics rather than becoming implicit wildcards.
- A wildcard string in a directory component visits every matching directory,
  recursively evaluates the remaining directory/name/type pattern, and returns
  pathnames containing the actual on-disk directory and file component case.
- Existing `:wild` and `:wild-inferiors` traversal behavior remains unchanged.

## Test-before evidence

Before implementation, the final name/type branch recognized only the special
`:wild` marker, and the ordinary directory branch used `string=` followed by an
early return. Embedded wildcard strings therefore matched nothing and could
not enumerate multiple directory branches. The initial focused test exited 1
because the required production wildcard matcher was absent.

## Acceptance evidence

`Lambda64/tests/host/test-file-fat32-wildcards.sh` extracts the production
matcher and recursive directory traversal into an executable FAT directory
facade. It covers zero-length and multi-star matches, a negative match,
case-insensitive exact lookup, simultaneous wildcard directory/name/type
components, multiple matching directories, and returned pathnames containing
their actual component case.

The focused host test passes. A guest FAT32 image directory query and the
required integration run remain outstanding, so this work item stays active.
