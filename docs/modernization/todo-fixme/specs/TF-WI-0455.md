# TF-WI-0455: Disk stream capacity boundary contract

## Scope

This specification closes the baseline requirement at
`Lambda64/tools/disk-stream.lisp:37`: disk-stream reads and writes must not
address bytes outside the capacity reported by `stream-file-length`.

## Invariants

For a read or write with current byte position `p`, requested byte count `n`,
and disk size `s`, the operation is valid exactly when:

```text
p >= 0, n >= 0, p <= s, and n <= s - p
```

The subtraction form is required so the check cannot accept an overflowing
`p + n` expression. A zero-length operation at `p = s` is valid.

## Failure semantics

An invalid operation signals the named, inspectable `disk-stream-bounds-error` before it
calls `disk-read` or `disk-write`. It leaves the stream position, supplied read
buffer, and disk contents unchanged. The condition exposes operation, position,
length, and disk size for diagnostics.

Existing sector alignment requirements remain in force after the capacity
check; this work item does not relax or redefine alignment.

The sequence methods retain the Gray stream return contract: a successful read
returns the first unfilled destination index, and a successful write returns
its input sequence.

## Acceptance evidence

`Lambda64/tests/host/test-disk-stream-bounds.sh` must verify all of:

1. an out-of-range read and write signal the boundary condition without I/O or
   position advance;
2. a request ending exactly at capacity succeeds and advances to EOF; and
3. a zero-length write at EOF succeeds without I/O.
4. successful read and write calls return their Gray stream contract values.

The focused test and `make test-fast` are required before the item can be
verified.
