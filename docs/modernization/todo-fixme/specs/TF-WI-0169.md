# TF-WI-0169: TCP abortive stream close contract

## Required behavior

`CLOSE` with `:ABORT T` synchronously publishes abort intent while holding the
connection lock, clears pending data and retransmission queues, disarms timers,
and schedules detachment on the network queue. Already-queued network work and
all send paths observe the intent and cannot send FIN, RST, or data. Normal
close retains the graceful FIN state machine.

## Evidence

The focused test directly executes the production `CLOSE` method. A deferred
FIFO queues an ACK first, invokes abort second, executes the ACK before detach,
and observes zero transmissions plus cleared queues; the following callback
detaches. A non-abort close still reaches `:FIN-WAIT-1` and sends FIN. On-wire
dispatch is recorded below the production `TCP4-SEND-PACKET` function, rather
than by a same-name guarded stub. Syntax-valid removal mutants for the abort
guards in `TCP4-SEND-PACKET`, `TCP-FLUSH-SEND-BUFFER`, `TCP-SEND-1`, and
`CLOSE-CONNECTION` are all rejected by unchanged-state assertions covering
sequence/state, queues, timers, and wire output. Actual scheduler concurrency
remain guest/network validation. Abort also records disarm operations for both
the retransmit and inactivity timers before detach is queued; removing either
disarm is rejected.
