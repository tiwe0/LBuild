# TF-WI-0403 — readtable 全锁

- **基线标记：** `TF-occ-c1c905c089b752c4e7334b64`
- **代码事实源：** `Lambda64/system/reader.lisp:17-85`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

读表的 base-character 向量与 extended-character 哈希表必须在并发读取和
修改时保持一致。由于 reader 在 cold start 阶段先于 supervisor mutex 初始化，
实现使用 readtable 内嵌的 CAS 原子标志，并以 `cpu-relax` 等待竞争者释放。

## 先测试证据

新增 `Lambda64/tests/host/test-system-reader-readtable-lock.sh`。测试检查锁字段、
CAS 获取/原子释放和读写路径的锁包裹，并确认删除读路径锁的变异会被拒绝。

## 验收标准

1. 每个 readtable 的语法读取和写入都经过同一排他锁。
2. 锁实现不依赖 cold start 之后才加载的 supervisor mutex。
3. 既有读表 API 与 `copy-readtable` 行为保持兼容。
4. codegen、cold image 和 integration 验证待完整构建环境恢复后执行，工作项保持 `active`。
