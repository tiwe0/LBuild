# TF-WI-0274: Snapshot disk-I/O world-stop boundary contract

## Scope

This item removes slow block-map and freelist writes from the global CPU stop.

## Required behavior

The snapshotter stops the world before acquiring `*VM-LOCK*`, performs wired
copying and CoW marking, resumes other CPUs, and retains the VM write lock while
it serializes the block map and freelist. The lock is released by
`UNWIND-PROTECT`. Thus unrelated threads can run during disk latency, while VM
metadata cannot change underneath serialization.

## Test-before evidence

The focused test reported the former disk-write-under-world-stop marker. The
original lexical nesting performed both recursive metadata writes while every
CPU remained stopped.

## Acceptance evidence

The focused test extracts and executes the production
`CALL-WITH-SNAPSHOT-VM-STABLE` and `TAKE-SNAPSHOT` forms. The orchestration
regression observes
`world-enter -> lock-acquire -> critical -> world-exit -> stable -> lock-release`,
asserts that both callbacks see the VM lock in their required scope, and proves
that either a critical- or stable-phase unwind releases the lock. This rejects
moving lock-ownership publication after the critical callback. Guest evidence
must measure scheduler progress during slow paging-disk writes.
