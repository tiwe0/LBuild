# TF-WI-0378: Total character encoding branch

## Scope

This work item closes the terminal `TODO character` error in the LLF character
encoder by making the advertised 21-bit input domain total.

## Required behavior

Codes through `#x7F`, `#x7FF`, and `#xFFFF` use one, two, and three bytes;
every remaining code through `#x1FFFFF` uses four bytes. Values outside the
implementation field are rejected by an explicit type check rather than an
unimplemented branch. Before using compact LLF character commands, the caller
checks the Unicode scalar upper bound and then asks `code-char`; thus neither
`#x110000` nor `#x1FFFFF` is passed to `code-char`, while in-range noncharacters
such as `#xFFFF` also take the constructor fallback. Valid Common Lisp Unicode
characters retain their prior byte sequences.

## Acceptance evidence

The focused host test executes `save-character` from the production source and
asserts exact bytes across `#x7FF/#x800` and the four-byte boundary. It also
executes the production character method with adapted codes `#xFFFF`,
`#x110000`, and `#x1FFFFF`, and verifies the saved constructor arguments and
`+llf-funcall-n+` command. The character-range mutant must fail. The pre-change
`HEAD` source exits 1 at the focused source-contract gate; the implemented
source prints both semantic and mutation-negative pass messages.

Guest execution for raw implementation-only codes is not yet recorded, so this
specification remains `active`.
