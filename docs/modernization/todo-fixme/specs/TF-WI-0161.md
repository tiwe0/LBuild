# TF-WI-0161: IPv4 pending ARP-send lifetime contract

## Scope

This specification closes the unbounded lifetime of packets queued by
`Lambda64/net/ip.lisp` while an IPv4 next-hop address is awaiting ARP
resolution. Successful immediate transmission and the existing bounded
ARP-update retry behavior remain unchanged.

## Required behavior

Every queued entry records its destination host, interface, packet, retry
count, and an absolute monotonic expiration time. The default retention period
is 30 seconds. Queueing an entry must independently schedule expiration on the
serial network queue; stale state cannot depend on another ARP packet arriving.

The outstanding-send mutex protects only generation, ownership, and list
state. Formatting, ARP lookup, ARP request transmission, and Ethernet packet
transmission must run after releasing it. An ARP update increments a generation
and atomically claims all pending entries before performing retries. A failed
claimed retry is returned to the list only if no newer ARP generation occurred;
otherwise it is retried immediately while remaining exclusively claimed.

The initial ARP lookup snapshots that generation before performing I/O. If a
reply is processed after the miss but before queue insertion, insertion observes
the changed generation and immediately claims a retry. This closes the lost
wakeup without allowing both the update path and insertion path to transmit the
same queued entry.

Expiration removes an entry when the current internal time is equal to or later
than its deadline. `arp-table-updated` must neither transmit nor retain expired
entries. A successfully retransmitted entry is removed, while an unsuccessful
non-expired entry retains its original deadline as its attempt count advances.
Entries restored from the prior four-field representation have no deadline and
are treated as expired rather than becoming immortal.

Interface shutdown continues to remove all entries belonging to that
interface, regardless of deadline.

## Test-before evidence

Before implementation,
`bash Lambda64/tests/host/test-net-ip-state-and-fragments.sh` exited with status
1 because the first required lifetime form,
`*outstanding-send-timeout*`, did not exist. The original entries contained
only four fields and could remain forever when no later ARP update occurred.

## Acceptance evidence

`Lambda64/tests/host/test-net-ip-state-and-fragments.sh` executes the real
queue, deadline predicate, expiration function, and scheduling helper. It
verifies all stored fields, preservation immediately before the deadline,
removal exactly at the deadline, the configured delay, and targeting of the
serial network queue. Its mutex facade asserts that every Ethernet attempt runs
at lock depth zero. A deterministic barrier makes an ARP update occur inside
the first miss before insertion, then proves one immediate successful retry,
no pending residue, and no second transmission on a later update. The ordinary
miss/update path also proves one claim and one successful retry.

The focused host test, Lisp style validation, documentation validation, and
whitespace-clean diffs cover the host-local contract. The ledger also requires
guest and integration evidence. No guest test has yet held a real unresolved
next hop past the deadline and observed both queue release and absence of a
late transmission, so this work item remains active.
