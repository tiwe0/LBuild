# TF-WI-0177: Reusable stack virtual-region contract

## Scope

This contract resolves the corresponding baseline directive in
`Lambda64/runtime/allocate.lisp` without changing its public allocator API.

## Required behavior

Stack allocation reserves a non-overlapping aligned virtual slot containing the
hard guard plus mapped stack. The complete free-list node is allocated before
entering `without-footholds` and the allocator mutex. Release only changes and
links existing cells while locked, so slow-cons/OOM cannot recursively acquire
the allocator lock. Released slots return once to a wired/non-wired pool;
failed and exceptional commits roll back before retry or unwind, and a repeated
finalizer invocation is a no-op.

## Test-before evidence

The strengthened source fixture first failed with
`stack virtual-region release allocates while linking`, exposing `push`/`cons`
under the allocator mutex. A production-direct commit-failure fixture then
locked the required rollback and exact reuse behavior before the implementation
was changed.

## Acceptance evidence

The production-direct fixture executes `allocate-stack-virtual-region`,
`release-stack-virtual-region`, and `%allocate-stack`. It injects a false commit
followed by success and a separate mapping exception, checks that the bump is
advanced only once, the same node is reused, no recursive lock occurs, and
unwind releases the lock. A shadowed slow-cons records that both node cells are
allocated at lock depth zero; forced slow-cons OOM proves no mapping, bump, free
list, or lock state is touched. Invoking the captured finalizer twice releases
the mapping and returns the region exactly once. Deleting the rollback call
must fail the fixture.

The focused fixture extracts and executes production forms while replacing only
Mezzano memory, tag, and atomic primitives with deterministic host facades. It
also rejects any remaining TODO/FIXME marker in the owned production file.

Cold-image boot, concurrent SMP allocation, pager fault handling, and long-run
GC behavior have not been exercised by this host run. This item remains active
until those integration requirements are verified in a guest image.
