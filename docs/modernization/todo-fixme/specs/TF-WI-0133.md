# TF-WI-0133: Non-terminal TO wild-inferiors pathname contract

## Scope

This specification replaces the former restriction at
`Lambda64/file/fs.lisp:647` that required `:WILD-INFERIORS` to be the final
`TO-WILDCARD` directory element.

## Required behavior

- A `:WILD-INFERIORS` element in `TO-WILDCARD` is replaced by the directory
  sequence captured from the corresponding `FROM-WILDCARD` wildcard.
- Components following `:WILD-INFERIORS` remain in the translated pathname and
  retain their declared order.
- An empty capture inserts no directory components but still preserves the
  following suffix.
- Captured strings continue to pass through the existing cross-host case
  correction policy.
- A `:WILD` destination element accepts exactly one captured directory level;
  it must consume a `:WILD` source capture.
- A `:WILD-INFERIORS` destination element consumes only the next
  `:WILD-INFERIORS` source capture. Destination wildcards must consume source
  captures in order and with matching types; a missing or type-mismatched
  capture signals an error. Trailing source captures may be discarded, and a
  literal destination may discard all source captures.

## Test-before evidence

Before implementation,
`FILE_FS_CASE=0133 bash Lambda64/tests/host/test-file-fs-semantics.sh` failed
with `:WILD-INFERIORS must be the last directory entry... (FIXME)` for a
translation to `(:ABSOLUTE "out" :WILD-INFERIORS "done")`.

The independent adversarial regression subsequently failed with `A TO
:WILD-INFERIORS consumed a FROM :WILD capture`; an extra destination wildcard
was also accepted rather than rejected. A follow-up compatibility regression
then failed with `Unused source directory wildcard captures...`, exposing an
overly strict check that rejected valid translations with fewer (or no)
destination wildcards.

## Acceptance evidence

`Lambda64/tests/host/test-file-fs-semantics.sh` directly executes the production
translation code. It verifies that a two-level capture produces
`(:ABSOLUTE "out" "a" "b" "done")` and that an empty capture produces
`(:ABSOLUTE "out" "done")`. Adversarial cases require errors for wildcard type
mismatch and destination wildcards without corresponding source captures.
Compatibility cases verify that `root/:WILD/:WILD` translated through
`out/:WILD` produces `out/one`, while a literal destination discards both
source captures.

The work item remains active until a booted Lambda64 guest and integration run
exercise equivalent logical-pathname translation rules.
