# TF-WI-0265: Explicit little-endian supervisor partition decoding

## Scope

This specification closes the byte-order portability requirement formerly
marked in `Lambda64/supervisor/partition.lisp`.

## Required behavior

Supervisor partition decoding must assemble 16-, 32-, and 64-bit little-endian
values from ordered octets. It must not depend on the CPU's native byte order,
unaligned native-width memory access, or an implicit host representation. The
optional index retains the existing element-index contract: it advances by two,
four, or eight octets for the corresponding width. Existing MBR, EBR, ISO-9660,
ATA, and AHCI callers of these helpers retain their numeric behavior.

GPT header and entry fields use these explicit readers, including the revision,
header size and CRC, all LBA fields, entry count, entry size, and entry-array
CRC.

## Acceptance evidence

`Lambda64/tests/host/test-supervisor-partition-gpt-validation.sh` replaces all
native-width memrefs with erroring fixtures and verifies known 32- and 64-bit
little-endian byte patterns plus end-to-end GPT and MBR decoding. The recorded
test-before failure was `Native-width 32-bit memref used`, proving the old
implementation still relied on native-width access. The focused host test
passes after implementation. Cold-image validation on supported supervisor
architectures and guest storage integration remain required before this item is
marked `verified`.
