# TF-WI-0140: Local supersede property-list merge contract

## Scope

This specification defines metadata replacement when a local output stream
opened with `:IF-EXISTS :SUPERSEDE` closes successfully.

## Required behavior

- A successful close installs the replacement file's storage and merges both
  property lists. Replacement-file values take precedence for shared
  indicators, while target-only and replacement-only properties are retained.
- Duplicate indicators in either source are canonicalized to one effective
  entry, preserving normal `GETF` first-occurrence precedence.
- The existing supersede timestamp behavior remains compatible: after the
  merge, `:CREATION-DATE` and `:WRITE-DATE` are both set to the successful close
  time.
- Replacement state is snapshotted under its file lock and installed with the
  merged target metadata under the target file lock.
- An aborted close does not replace storage or merge properties.

## Test-before evidence

Against the baseline source, the isolated `FILE_LOCAL_CASE=0140` focused host
contract failed with `Replacement property did not override the old property
(expected "new", got "old")`. The old method retained target metadata but did
not merge replacement metadata into it.

## Acceptance evidence

`Lambda64/tests/host/test-file-local-semantics.sh` directly executes the
production close method. It covers target-only, replacement-only, overriding,
duplicate, timestamp, storage-swap, and abort behavior. The focused host test
must pass.

The work item remains active until the required guest and integration levels
open a real `LOCAL:` stream with `:IF-EXISTS :SUPERSEDE`, set properties through
the file API, close and reopen it, and verify persisted metadata.
