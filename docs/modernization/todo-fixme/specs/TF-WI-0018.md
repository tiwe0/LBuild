# TF-WI-0018: Lower ARM64 integer memref CAS through SSA-safe CAS IR

## Scope

`Lambda64/compiler/backend/arm64/memory.lisp:79`.

## Current boundary

`%memref-{signed,unsigned}-byte-{8,16,32,64}` CAS lowers through the backend-only
`arm64-cas-mem-instruction` (`Lambda64/compiler/backend/arm64/arm64.lisp:133`,
`memory.lisp:129-154`). The generic compare-exchange IR used by object/slot CAS
stores an object plus slot displacement/index (`x86-cmpxchg-instruction`), not an
arbitrary effective address. ARM64 memref addresses also require the scaled
base/index address builder and byte-width-specific `CASAL{B,H,W}` or `CASAL`
selection. DCAS additionally needs a 16-byte acquire/release instruction and a
pair-result/clobber contract; no such ARM64 backend instruction exists today.

Therefore `(cas memref-t)` and `dcas memref-t` remain intentionally unsupported.
The existing integer CAS path is the safe boundary: old/new/current values use
distinct virtual registers and preserve boxing plus acquire/release semantics.

## Required evidence

Before removing the marker, add a generic IR form carrying arbitrary addresses,
explicit memory-order metadata, and (for DCAS) two old/new/result values. Add
ARM64 lowering and register-allocation tests for unscaled/scaled offsets,
unaligned rejection, and 16-byte alignment, then run guest concurrency stress
against the generated code. The current host boundary test verifies the marker,
all blocker tokens, and rejects a mutation that removes the marker.
