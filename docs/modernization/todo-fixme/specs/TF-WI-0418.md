# TF-WI-0418 — `CONCATENATE` vector result length

- **Baseline marker:** `TF-occ-c3e4334d938df99e3f0bbced`
- **Code source of truth:** `Lambda64/system/sequence.lisp:468-555`
- **Risk:** high
- **Required test levels:** host, cold-image, integration

## Objective

`vector-type-element-type` returns both the upgraded vector element type and a
known one-dimensional length restriction. `CONCATENATE` propagates that
restriction through its compiler macro and runtime vector path. A result type
such as `(vector base-char 2)` succeeds only when exactly two elements are
provided; unrestricted vector types retain `*` and accept their computed
length.

## Test-first evidence

Before implementation,
`Lambda64/tests/host/test-system-sequence-vector-result-length.sh` failed:

```text
vector result type did not return its fixed length: NIL
```

The test covers direct vector and `simple-array` forms, wildcard vector length,
the compiler-macro expansion, and both `%concatenate-vector` and the public
`concatenate` runtime entry. It exercises successful fixed-length concatenation
and a too-long result. Its mutation case removes the length comparison; the
too-long result then fails to signal the required `simple-type-error`.
