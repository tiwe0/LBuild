# TF-WI-0339: Document constructor initarg parsing boundary

## Scope

`Lambda64/system/clos/constructor.lisp:69` retains a high-risk modernization marker.

## Current boundary

The optimized constructor path currently parses initargs with GETF/GET-PROPERTIES instead of generated &KEY machinery. This preserves slot initarg semantics while avoiding a dependency on generic-function lambda-list compilation.

## Required evidence

Keep the marker active until a compatible &KEY implementation is proven across duplicate keys, :allow-other-keys, initarg validation, and standard/functionable constructors at host, cold-image, and integration levels.
