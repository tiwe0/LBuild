# TF-WI-0064 — PURE-P call argument-count contract

`pure-p` may classify a call as side-effect free only when the callee is in the
compiler's pure-function allowlist **and** the call uses a valid arity. Unary
entries require exactly one argument, binary entries require exactly two,
`list` accepts zero or more, and `list*` requires at least one. Nested
arguments must remain pure. Unsupported arities are not pure so they cannot be
removed by simplification.

The focused host regression is `Lambda64/tests/host/test-compiler-pure-call-arity.sh`.
It checks the implementation contract and runs a mutation-negative pass that
removes the arity guard and must fail.
