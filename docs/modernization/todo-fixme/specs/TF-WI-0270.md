# TF-WI-0270: Dirty wired-page snapshot copy contract

## Scope

This item replaces the unconditional wired-page copying path in
`Lambda64/supervisor/snapshot.lisp`.

## Required behavior

- On architectures with reliable wired-page dirty tracking, only present dirty
  pages receive a new store block and enter the writeback list.
- After a stable copy, the dirty bit is cleared with a system-wide TLB
  shootdown so later snapshots can skip an unchanged page.
- ARM64 remains deliberately conservative because its writable wired mappings
  do not emulate later dirty transitions; it copies every present wired page
  rather than risking persistence loss.

## Test-before evidence

The focused host test initially reported the original marker at line 65 and no
dirty-selection helper. The executable regression distinguishes dirty, clean,
and conservative-architecture decisions.

## Acceptance evidence

`test-supervisor-snapshot-semantics.sh` extracts and executes the production
`MAP-SNAPSHOT-WIRED-PAGES` and `SNAPSHOT-COPY-WIRED-AREA` forms. It verifies
dirty filtering, backing-page copying and writeback publication, dirty-bit
clearing, the complete TLB shootdown sequence, and sparse card-table traversal.
This rejects mutations that remove either dirty clearing or TLB maintenance. A
booted guest must still verify hardware PTE dirty-bit transitions and persisted
bytes on both architectures.
