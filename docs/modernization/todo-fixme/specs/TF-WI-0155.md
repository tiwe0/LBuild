# TF-WI-0155: Virgl DMA command-buffer submit contract

## Scope

This specification replaces the unconditional failure in the DMA branch of
`command-buffer-submit` in `Lambda64/gui/virgl/virgl.lisp` with an operational
virtio-gpu submission path.

## Required behavior

A finalized command buffer with no DMA storage continues to call
`virgl-submit-simple-command-buffer-1`. A finalized command buffer with DMA
storage submits the already encoded DMA request without copying its command
stream through `gpu:virtio-gpu-submit-3d` and without enforcing that API's
internal-buffer size limit.

The DMA path returns success only for `VIRTIO_GPU_RESP_OK_NODATA`. A device
error or inability to construct the descriptor chain must use
`simple-virgl-error` with the command buffer's context and the returned numeric
error code. Queue descriptors must be released on successful, device-error,
and host-side descriptor-allocation failure paths.

Repeated submission of one finalized optimized command buffer must remain
valid: submission does not mutate, release, or detach its DMA storage.

## Test-before evidence

The pre-change DMA branch was exactly `(error "TODO")`, so every optimized or
large command buffer failed before reaching virtio. The first focused host test
run against that source exited nonzero because the DMA submit helper and request
contract were absent.

## Acceptance evidence

`Lambda64/tests/host/test-virgl-command-buffer.sh` executes a successful DMA
submit through an instrumented virtqueue, verifies one queue kick and complete
descriptor cleanup, and separately injects a non-success device response and
descriptor exhaustion. Both failures must reach the virgl error path; the
descriptor-exhaustion case must not kick the queue. The same test proves that
the pre-existing small copying path is unchanged and that large buffers select
DMA automatically.

The required guest evidence is not yet available. A real image must submit an
optimized command buffer through QEMU/virtio-gpu and demonstrate correct virgl
output before this work item can be marked verified.
