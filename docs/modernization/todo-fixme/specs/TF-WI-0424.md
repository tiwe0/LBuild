# TF-WI-0424 — thread-pool 待执行工作优先级

- **基线标记：** `TF-occ-bf0ea57725d4c62448ef3075`
- **代码事实源：** `Lambda64/system/thread-pool.lisp:157-189`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`thread-pool-add` 必须使其 `priority` 参数对尚未开始执行的工作生效：`:high`
优先于普通工作（`nil`、`:normal` 或未知值），普通工作优先于 `:low`；同一优先级按
提交顺序保持 FIFO。已经由 worker 取走的工作不抢占，未知 priority 按历史的忽略参数
行为保留为普通工作。`thread-pool-add-many` 继续将调用者给出的 priority 传递给每项。

## 先测试证据

新增 `Lambda64/tests/host/test-system-thread-pool-priority.sh`，它从生产源提取
`work-item`、priority 映射和入队定义，并在最小 thread-pool 模型中验证混合优先级的
待执行顺序及同级 FIFO。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-thread-pool-priority.sh
```

失败并报告：

```text
thread-pool priority is ignored
```

证明原实现显式忽略了 `priority` 参数。变异负例将 `:high` 与普通工作的 rank 合并；
测试必须拒绝该变异。

## 验收标准

1. `:high`、普通和 `:low` 的待执行顺序分别为高、普通、低。
2. 同一 priority 的多个 work item 保持原提交次序。
3. 正在运行的 work item 不被新的高优先级工作抢占。
4. 未识别的 priority 仍按旧版本的等效普通队列行为处理。
5. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。
