# TF-WI-0157: XTerm Meta input translation contract

## Scope

This specification closes the missing Meta input behavior in
`Lambda64/gui/xterm.lisp` using fixed `metaSendsEscape` semantics. It changes
only terminal-client input translation; keyboard modifier discovery and
physical key mapping in `Lambda64/gui/compositor.lisp` are outside this work
item. In particular, the existing Right-Meta to `:shift2` mapping is unchanged.

## Required behavior

- A character carrying `:meta`, but neither `:super` nor `:hyper`, first emits
  `ESC`. The translator then removes only the Meta bit and processes the
  resulting character through the existing Control, translated-key, or
  ordinary Unicode input path.
- `M-C-a` therefore emits `ESC` followed by control-A.
- `M-Up` emits `ESC` followed by the existing Up sequence `ESC [ A`.
- `M-ESC` emits two Escape characters.
- A Meta-modified non-ASCII character emits `ESC` followed by that unchanged
  Unicode character.
- A character carrying `:super` or `:hyper` remains unsupported and emits
  nothing. Adding Meta to either unsupported modifier must not weaken that
  rejection.
- Input without Meta keeps its existing translation behavior.

## Test-before evidence

Before implementation,
`Lambda64/tests/host/test-xterm-meta-input.sh` was run with `XTERM_SOURCE`
pointing at `git show HEAD:Lambda64/gui/xterm.lisp`. It exited with status 1 at
the first contract assertion: `M-C-a produced "", expected ESC control-A`.

## Acceptance evidence

`Lambda64/tests/host/test-xterm-meta-input.sh` extracts and executes the real
`input-translate` definition with a host adapter for Mezzano's modifier-bearing
characters. It covers `M-C-a`, `M-Up`, `M-ESC`, Meta plus a non-ASCII
character, Super/Hyper with and without Meta, and the corresponding existing
non-Meta Control, translated-key, and Unicode paths. Because SBCL's character
representation cannot carry Mezzano modifier bits, the test also structurally
asserts that the immutable replacement returned by `set-char-bit` is assigned
back to `character`. Its Meta Up-Arrow proxy returns a distinct ordinary
Up-Arrow character only when Meta is cleared, so the expected translated key
sequence fails if the implementation ignores that replacement; a text match
alone is not accepted as the representation-level guarantee.

The focused host test, documentation validation, and diff whitespace check are
required evidence for this slice. The work-item ledger also requires guest
evidence. No guest execution is recorded here, and the ledger is not frozen,
so this work item must not be marked verified yet.
