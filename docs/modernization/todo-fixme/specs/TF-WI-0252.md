# TF-WI-0252: Enforce disk driver transfer limits

## Scope

Resolve the transfer-size FIXME at `Lambda64/supervisor/disk.lisp:187`.
`disk-max-transfer` is the per-driver limit in sectors (for example, AHCI and
VirtIO advertise finite limits); `N-SECTORS` requests larger than that limit
must not be passed to a callback that may only accept one bounded transfer.

## Contract

`process-one-disk-request` rejects a positive request exceeding a positive
`disk-max-transfer` before buffer setup or driver invocation, returning the
stable error reason `"Disk request exceeds device transfer limit."`. A `NIL` or
zero limit remains unlimited for existing devices. Rejection occurs before any
bounce-buffer allocation; existing `unwind-protect` cleanup remains the guard
for accepted read/write requests.

Request splitting is intentionally not performed here: the disk request is a
single asynchronous object with one buffer and completion latch, while driver
callbacks have no partial-progress contract. Callers that need larger reads
(such as GPT probing) already split using `disk-max-transfer`.

## Acceptance evidence

`Lambda64/tests/host/test-supervisor-disk-transfer-limit.sh` checks the guard,
error reason, and cleanup contract. Set
`DISK_TRANSFER_LIMIT_MUTATION_RUN=1` to remove the comparison; the test must
then fail, proving mutation sensitivity.
