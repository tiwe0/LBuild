# TF-WI-0425 — `decode-universal-time` DST

- **基线标记：** `TF-occ-9b2408950481df1b533eff23`
- **代码事实源：** `Lambda64/system/time.lisp:20`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`decode-universal-time` 在未显式传入 `time-zone` 时，通过可配置的
`*daylight-saving-time-function*` 解析器取得 DST 状态和实际 UTC 偏移；显式
`time-zone` 继续使用 Common Lisp 要求的固定偏移。解析器接收
`(universal-time configured-time-zone)`，返回 `(daylight-p seconds-west)`。
`seconds-west` 是用于解码本地时间的实际偏移；当 `daylight-p` 为真时，返回值
中的时区仍按 Common Lisp 约定报告对应的标准时区（实际偏移加一小时）。
未配置解析器时保留原有固定偏移行为。由于当前内核只保存数值时区而没有
IANA/本地时区规则数据库，具体地区规则由平台或启动代码注入，不能在此层
安全猜测。

## 先测试证据

新增 `Lambda64/tests/host/test-system-time-dst.sh`，在 host 的 SBCL 最小环境
中加载生产 decode 实现，验证：解析器收到正确参数并传播 DST/偏移；显式
`time-zone` 不调用解析器且保持固定偏移。

```sh
bash -n Lambda64/tests/host/test-system-time-dst.sh
bash Lambda64/tests/host/test-system-time-dst.sh
```

实现前基线没有解析器入口，无法表达或验证 DST；测试随后证明该契约。

## 验收标准

1. 未提供 `time-zone` 且配置解析器时，用解析器给出的 DST 标记和实际偏移解码
   本地时间，并按 Common Lisp 约定报告标准时区。
2. 提供 `time-zone` 时，解析器不会被调用，DST 为 `NIL`，偏移等于参数。
3. 未配置解析器时，历史 `*time-zone*` 固定偏移行为保持不变。
4. 地区规则由注入的解析器负责；本层不伪造不完整的地区规则。
5. cold image 与 QEMU integration 仍需完整环境验收，工作项保持 `active`。

## 当前证据

上述 `bash -n` 与 host 回归测试均通过。cold image/integration 尚未执行，故
工作项保持 `active`。
