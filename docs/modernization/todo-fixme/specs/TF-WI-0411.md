# TF-WI-0411 — 数值一维数组哈希的非零起点

- **基线标记：** `TF-occ-88709dc6e4871c9064c8c156`
- **代码事实源：** `Lambda64/system/runtime-array.lisp:579`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`hash-simple-numeric-1d-array` 必须支持任意合法 `[start,end)` 区间，而不是仅
接受 `start = 0`。非零起点的哈希只包含请求的逻辑元素，并把最后一个不完整的
32 位字高位按零处理；越界、倒置或非整数范围必须在读取底层存储之前被拒绝。

为避免改变已有字符串和数组哈希的既有分布，`start = 0` 路径保留原有逐字和
尾字掩码规则，特别是 packed 1/2/4-bit 数组的完整尾字行为。

## 先测试证据

新增 `Lambda64/tests/host/test-system-runtime-array-hash-slices.sh`。该测试从
生产源中提取实际函数，提供底层 32 位存储替身，并以独立的逐位参考实现验证
每种支持的元素宽度。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-runtime-array-hash-slices.sh
```

在首个非零区间（1-bit 数组的 `[1,12)`）失败，原始函数报出
`TODO: Non-zero start`。

## 验收标准

1. 所有支持的 1、2、4、8、16、32、64、128 位元素表示均支持非零 `start`。
2. 跨 32 位字边界的切片、空切片和省略 `end` 都按请求区间的长度和位序列哈希。
3. 零起点哈希与原实现的字级行为保持一致，包括 packed 数组的历史尾字规则。
4. 负数、倒置、越界和非整数范围在读存储前报错。
5. host 测试直接加载生产定义，并通过将 `(* start element-bits)` 变为零的
   变异负例；cold image 与 QEMU integration 仍需在后续完整测试阶段补齐。
