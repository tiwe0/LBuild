# TF-WI-0141: Remote pathname junk parsing contract

## Scope

This specification resolves the `:junk-allowed` gap in
`Lambda64/file/remote.lisp` without narrowing the remote file protocol's
existing pathname component grammar.

## Required behavior

- Both ordinary and `:junk-allowed t` parsing return the parsed pathname and the
  position immediately after its representation.
- The remote grammar continues to consume the complete namestring: `/`
  separates directory components, while other characters, including spaces,
  remain legal inside a component and must not be invented as junk delimiters.
- Existing absolute and relative paths, `.`, `..`, `*`, `**`, final name/type
  splitting, and the trailing `~` previous-version convention remain intact.
- An empty namestring produces a host-only pathname and returns position zero.
- Missing final name/type values, including a trailing directory separator,
  must not be passed to string-only wildcard comparisons.

## Test-before evidence

Before implementation, the focused test substituted the baseline remote
source while retaining the implemented HTTP slice. It reached the first remote
parse using `:junk-allowed t` and failed with the old implementation's
`TODO: Junk-allowed` error.

## Acceptance evidence

The focused host test loads the remote parser form from the real source and
verifies an absolute typed backup pathname, a legal space inside a relative
component, full-consumption positions, the empty-namestring boundary, a
trailing directory with nil name/type/version, `:wild-inferiors`, and independent
wild name/type components.

The focused host test, `make lisp-style-check`, and a whitespace-clean diff are
required for this slice. The ledger also requires guest and remote-file-server
integration coverage. Those levels are not recorded here, so this item remains
active.
