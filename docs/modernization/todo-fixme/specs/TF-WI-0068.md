# TF-WI-0068: multiple-value type-check lowering boundary

## Scope

The complicated `ast-the` path currently preserves all values with
`multiple-value-call` and re-checks each required/optional/rest value.

## Current boundary

The existing lowering is intentionally straightforward and allocates temporary
bindings. Replacing it with an M-V-P1-style save-and-inspect sequence requires
proving value-count preservation, rest-list dynamic extent, and equivalent error
ordering across optimized safety-3 code. The marker remains active pending that
codegen evidence.

## Required evidence

Add compiler, allocation, and host regression tests comparing value counts,
error behavior, and generated code for required/optional/rest value types before
removing the marker.
