# TF-WI-0045 — 交叉引导结构重定义兼容性

- **基线标记：** `TF-occ-88faf290841b1274c0e5708a`
- **代码事实源：** `Lambda64/compiler/cross-boot.lisp:212-229`
- **风险：** critical
- **要求测试层：** host、codegen、cold-image

## 当前边界

`sys.int::%defstruct` 在交叉引导期间遇到同名结构定义时直接返回新定义，尚未比较父类、槽定义、布局、大小、区域及 sealed 等字段。该路径影响后续结构访问器和冷启动镜像的一致性；任意局部比较都可能错误地接受不兼容定义或拒绝合法的重复加载，因此不能作为低风险清理处理。

## 当前证据

代码审查确认现有运行时拥有 `structure-definition-trivially-compatible-p`，但其输入是运行时 class 与定义，不等价于 cross-bootstrap 的 `*structure-types*` 表比较；未发现可直接复用且覆盖全部布局字段的交叉引导比较器。marker 保持 active，未宣称实现完成。

## 后续验收

1. 建立跨引导结构定义的兼容性谓词，覆盖父类、槽顺序/类型/访问器、布局、大小、区域、sealed 与构造器标志。
2. 对完全相同定义保持幂等；对任一 ABI/布局不兼容定义在 host、codegen 和 cold-image 层失败并给出可诊断条件。
3. 增加重复加载、兼容重定义和不兼容重定义的 focused regression test 后，才可移除 marker。
