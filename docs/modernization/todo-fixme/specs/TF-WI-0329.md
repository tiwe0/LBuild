# TF-WI-0329: Thread-safe weak EQL dispatch table

## Scope

This work item closes the corresponding CLOS runtime marker in
`Lambda64/system/clos/closette.lisp`.

## Required behavior

- Single-dispatch EQL keys are weak and every weak-alist traversal is serialized by its dedicated mutex.
- Existing bootstrap-safe paths and standard generic-function fast paths remain available.

## Test-before evidence

The old discriminator retained EQL keys strongly in an ordinary alist. The focused source-contract test failed against that implementation.

## Acceptance evidence

`Lambda64/tests/host/test-system-closette-modernization.sh` checks the production
forms for this contract. `test-system-closette-behavior.sh` directly extracts
`one-effective-eql-table-assoc`; its mutex facade dynamically records ownership,
and the weak-alist facade signals if lookup occurs outside that critical section.
An empty mutex body followed by an unlocked lookup is therefore rejected. The
focused tests and Lisp style checks pass. A cold-image build and guest
CLOS redefinition/dispatch exercise remain outstanding, so this item stays active.
