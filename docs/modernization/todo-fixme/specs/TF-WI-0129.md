# TF-WI-0129: ext4 inline data block contract

## Scope

This specification closes the block-sizing defect in the inline-data branch of
`do-file` in `Lambda64/file/ext4.lisp`.

## Required behavior

An inode carrying `EXT4_INLINE_DATA_FL` must provide the file-cache callback
with exactly one filesystem-sized octet array. The inode's 60-byte `i_block`
payload is copied unchanged to the start of that array and the remainder is
zero-filled. A filesystem block smaller than the stored payload is rejected
instead of silently truncating data.

This work item does not change the existing read-only filesystem boundary or
add extraction of optional inline bytes from the inode extended-attribute
area; it corrects the callback buffer contract for the inline payload currently
decoded by `read-inode`. Consequently, an inline file whose content extends
into the `system.data` inode xattr is not fully supported by this work item and
requires a separate inode/xattr parsing and guest-image contract.

## Test-before evidence

Before implementation, the inline-data branch passed the raw 60-byte `i_block`
array directly to consumers even though file-cache blocks use the filesystem
block size. The focused shared test initially failed before reaching this case
because the companion extent-tree implementation was absent.

## Acceptance evidence

`Lambda64/tests/host/test-file-ext4-extents.sh` invokes the extracted production
`do-file` with a 128-byte mock filesystem block. It proves the callback length,
all 60 payload bytes, and zero padding through the end of the block.

The focused host test passes. A guest read of a real inline-data inode and the
required integration run remain outstanding, so this item stays active.
