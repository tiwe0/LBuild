# TF-WI-0067: allow-other-keys type-check boundary

## Scope

The `ast-the` type-check lowering path in `Lambda64/compiler/type-check.lisp`
parses required, optional, and rest value types but has no separate
`&ALLOW-OTHER-KEYS` policy.

## Current boundary

`&ALLOW-OTHER-KEYS` is a lambda-list keyword-processing rule, not a value-type
specification. Type-check lowering must preserve the caller's value count and
report type failures without changing keyword argument acceptance semantics; the
marker remains active until these contracts are covered together.

## Required evidence

Add compiler and host tests proving type checks around keyword calls with and
without `&ALLOW-OTHER-KEYS`, including unknown-key and multiple-value cases,
before removing the marker.
