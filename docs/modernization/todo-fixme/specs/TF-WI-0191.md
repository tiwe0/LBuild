# TF-WI-0191 — x86-64 APPLY 参数数量上限

- **基线标记：** `TF-occ-e3d7c983364a2c1d5664b014`
- **代码事实源：** `Lambda64/runtime/runtime-x86-64.lisp:%apply`
- **风险：** critical
- **要求测试层：** host、cold-image、integration

## 目标

`%apply` 在拆包参数列表时必须执行 `CALL-ARGUMENTS-LIMIT`（当前值 500）。上限是排他的：499 个参数继续调用；第 500 个参数在继续增长临时参数栈前报告 `program-error`，而非
无界地拆包并尝试调用。

## 先测试证据

新增 `Lambda64/tests/host/test-runtime-apply-arguments-limit.sh`。测试检查 guard 使用
编码后的 `CALL-ARGUMENTS-LIMIT`、在列表遍历前执行，并确认移除分支的 mutation 会被拒绝。

## 验收标准

1. x86-64 `%apply` 在参数计数达到上限时报告程序错误。
2. 上限减一仍被接受，上限值被拒绝，proper-list 类型检查语义保持不变。
3. 错误路径先丢弃临时栈参数并保持调用栈对齐。
4. cold-image 与 integration 验证待完整构建环境可用后执行，工作项保持 `active`。

## 当前证据

```sh
bash -n Lambda64/tests/host/test-runtime-apply-arguments-limit.sh
bash Lambda64/tests/host/test-runtime-apply-arguments-limit.sh
```

两项均已通过；后者同时确认移除 CALL-ARGUMENTS-LIMIT 分支的 mutation 被拒绝。
