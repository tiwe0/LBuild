# TF-WI-0264: Multi-sector supervisor GPT entry-array contract

## Scope

This specification closes the single-sector GPT entry-array limitation formerly
marked in `Lambda64/supervisor/partition.lisp`.

## Required behavior

The supervisor must derive the exact partition-entry byte length from the GPT
header, validate that its sector-rounded range fits before the first usable LBA
and within the disk, allocate enough wired pages for the complete range, and
read every required sector. Reads must be split at `disk-max-transfer` so a
valid table larger than either one sector or one device transfer remains
readable. Entry offsets are relative to that complete buffer; entries may not be
decoded from a one-sector buffer when they lie in a later sector of the array.

Allocation or entry-array I/O failure rejects that GPT copy without publishing
partial partitions and allows backup-header recovery. MBR and ISO-9660 fallback
behavior remains unchanged when both GPT copies fail validation.

## Acceptance evidence

`Lambda64/tests/host/test-supervisor-partition-gpt-validation.sh` constructs a
standards-sized 128-byte entry array spanning two 512-byte sectors and selects
an entry stored in the second sector, using a mock disk limited to one sector
per transfer. It proves both entry-array sectors are read and the later entry is
decoded with the expected start and size. Before
implementation the same fixture failed while the old one-sector decoder was
still active. The focused host test passes after implementation. A cold-image
boot and guest integration test against a real GPT block device are still
required before changing this specification to `verified`.
