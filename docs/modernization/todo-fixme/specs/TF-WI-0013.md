# TF-WI-0013: Emit ARM64 NLX jump tables as trailers

## Scope

`Lambda64/compiler/backend/arm64/codegen.lisp:900`.

## Current boundary

NLX jump-table words are currently emitted inline. Moving them to a trailer affects labels, PC-relative offsets, alignment, and cold-image serialization; retain marker until codegen and runtime NLX tests cover all target counts.

The current LAP pipeline returns a flat instruction list from
`perform-target-lap-generation`; it has no function-level trailer channel.
`emit-lap` resolves labels during the prepass and emits `(:d64/le ...)` words
inline, while the cold serializer consumes the resulting list in order. A
safe implementation therefore needs a new trailer field (or equivalent
structured result) propagated through the backend and serializer, plus an
explicit alignment/range check for ARM64 `ADR` references. Until that channel
exists, retaining the inline table is the only ABI-preserving behavior.

### Minimal implementation design

1. Add a per-function trailer vector to the LAP-generation result without
   changing existing instruction ordering.
2. Record each NLX table (label and target expressions) in that vector during
   `emit-lap`, and emit a short branch-over stub only when required by the
   selected layout.
3. Teach cold serialization to place and align trailer vectors after the code
   body, then resolve `ADR`/`:d64/le` expressions against the final labels.
4. Add codegen and guest NLX fixtures covering zero, one, and many targets and
   rejecting out-of-range PC-relative references.

## Required evidence

Add focused code-generation tests plus the relevant host/guest integration test before removing the marker. The test must cover the architectural boundary, unchanged behavior for existing inputs, and failure/overflow behavior where applicable.
