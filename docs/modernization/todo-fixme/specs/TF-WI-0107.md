# TF-WI-0107: USB mass-storage write-protection detection

## Scope

This specification closes the corresponding baseline marker formerly present
in `Lambda64/drivers/usb/mass-storage.lisp` while preserving the USB bulk-only
transport and block-device interfaces.

## Required behavior

Probe registration derives `:writable-p` from the SCSI MODE SENSE(6) mode-header WP bit. A set WP bit, failed command, or invalid CSW status fails closed as read-only; a phase error also performs bulk-only reset recovery.

## Acceptance evidence

`Lambda64/tests/host/test-drivers-usb-mass-storage-semantics.sh` extracts and
executes the production encoders, structured timeout condition,
`probe-transfer`, `parse-inquiry`, `parse-read-capacity`, and
`probe-writable-p` under SBCL with mocked events, bulk queues, CSW responses,
and reset recovery. It covers NACA off/on encoding, MODE SENSE(6) CDB bytes,
successful transfer ordering, direct timeout injection at all six
inquiry/read-capacity phases, diagnostic fields and queue cleanup,
writable/read-only WP results, and failed, invalid (`#xFF`), and phase-error
CSWs. The invalid-status assertion directly calls the production
`probe-writable-p`; the phase-error case continues to assert reset recovery.
Source mutations that remove timeout dequeue or change the invalid-CSW
`otherwise` branch to return true are rejected. The original recorded
test-before failure was `Missing mass-storage production form:
(define-condition mass-storage-transfer-timeout`; reviewer hardening also
recorded `Missing focused regression: invalid CSW fails closed` before adding
the new assertion. The implemented source prints `USB mass-storage production
semantics passed` and `USB mass-storage integration contract passed`.

The work item also requires `hardware-usb-mass-storage`. No physical USB
mass-storage device or Mezzano guest was available for this pass, so real BOT
stall/reset timing, device-specific MODE SENSE support, removable-media write
protection, and hardware queue cancellation remain unverified. The
specification therefore remains `active`.
