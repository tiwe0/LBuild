# TF-WI-0149: TGSI numbered immediate contract

## Scope

This specification resolves the numbered-immediate gap in
`Lambda64/gui/virgl/tgsi.lisp` while preserving the existing unnumbered form.

## Required behavior

An unnumbered immediate remains `(imm type values)` and is emitted as
`IMM TYPE {...}`. A numbered immediate is `(imm index type values)` and is
emitted as `IMM[index] TYPE {...}`.

The index is an unsigned 32-bit integer and must equal the next implicit
immediate number. Unnumbered and numbered declarations share one sequence.
This mirrors Mesa's TGSI text reader, which rejects gaps, reordering, and
duplicates rather than treating the bracket as an arbitrary identifier.

## Test-before evidence

Before implementation, the focused host fixture's numbered form failed during
destructuring because the old assembler accepted exactly two immediate
arguments. It had no immediate sequence state and could not emit `IMM[n]`.

## Acceptance evidence

`Lambda64/tests/host/test-virgl-tgsi-parser.sh` verifies a mixed sequence with
an unnumbered index 0 followed by explicit indices 1, 2, and 3, the exact text
output, unchanged five-token accounting per immediate, and early rejection of
a sequence starting at index 1.

The focused host test, `make lisp-style-check`, and a whitespace-clean diff are
required for this slice. The ledger additionally requires a guest virgl test
that submits numbered-immediate shader text. No such GPU-backed evidence is
recorded here, so this item remains active.
