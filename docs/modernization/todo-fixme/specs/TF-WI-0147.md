# TF-WI-0147: GUI image weak-cache contract

## Scope

This specification resolves the image-cache lifetime gap in
`Lambda64/gui/image.lisp`. It changes only cache retention; decoding order,
pathname canonicalization, cache synchronization, explicit flushing, and
surface contents remain unchanged.

## Required behavior

`*image-cache*` maps canonical pathnames to decoded image surfaces using an
`equal`, synchronized hash table with `:value` weakness. While a caller holds a
surface strongly, another load of the same canonical pathname returns that
same surface without decoding it again. Once the surface is otherwise
unreachable, a major collection may remove the cache entry; a later load then
decodes a replacement surface.

Value weakness is intentional. The decoded surface is the disposable resource,
whereas the pathname is only its lookup key. Mezzano's weak-table implementation
stores an entry as a weak pointer whose `:value` processing keeps the key alive
only while the value is live. This prevents both the image and its cached
pathname from being retained solely by the cache. A weak-key table would not
express that resource-lifetime contract, and a strong table would retain every
decoded surface until an explicit flush.

This is normal weak-reference behavior, not a soft-reference policy: the
runtime has no memory-pressure-sensitive soft-reference API. Callers must not
depend on an unreferenced image remaining cached across a major collection.

## Test-before evidence

Before the implementation, the focused host fixture failed with
`Image cache must use value weakness, got NIL`. The original strong hash table
retained every decoded surface until `flush-image-cache` was called.

## Acceptance evidence

`Lambda64/tests/host/test-gui-image-weak-cache.sh` executes the real cache
definition, `flush-image-cache`, and `load-image` against a deterministic image
decoder facade. It verifies the table's value-weakness mode, live-reference
cache hits, collection and re-decoding after the last strong surface reference
is removed, and explicit flushing.

The focused host test, `make lisp-style-check`, and whitespace-clean diffs are
required for this slice. The work-item ledger also requires guest evidence. The
host runtime proves Common Lisp value-weak table behavior and the real image
cache control flow, but does not execute Mezzano's collector in a guest; this
item must not be marked verified until guest GC evidence exists.
