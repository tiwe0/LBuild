# TF-WI-0062 — 编译器 `MACROLET` 文档字符串处理

- **基线标记：** `TF-occ-5dd618da41a153f46ca09301`
- **代码事实源：** `Lambda64/compiler/pass1.lisp`
- **风险：** critical
- **要求测试层：** host、codegen、cold-image

## 目标

`hack-macrolet-definition` 必须按 Common Lisp 宏定义体语法接受可选文档字符串。
文档字符串由 `parse-declares` 识别并从实际宏展开体中移除，不能作为运行期扩展
form 发射；其后的声明和宏展开 forms 仍保持原有顺序与语义。

仅有一个字符串 form 时，该字符串是宏体的最终值而不是文档字符串，必须继续
参与展开。该边界遵循共享 `parse-declares` 的“末尾字符串始终是 body form”契约。

## 先测试证据

先新增 `Lambda64/tests/host/test-compiler-pass1-macrolet-docstring.sh`，从生产
`pass1.lisp` 提取并执行 `hack-macrolet-definition`。实现前运行：

```sh
bash Lambda64/tests/host/test-compiler-pass1-macrolet-docstring.sh
```

测试失败并报告 `MACROLET docstring was emitted as an executable form`：旧实现调用
`parse-declares` 时未启用 `:permit-docstring t`，因此字符串仍留在生成的宏体中。

## 验收标准

1. 带后续展开 form 的前导文档字符串被接受，但不会出现在生成的 expansion
   lambda 中。
2. 宏名、参数解构、声明和宏展开结果保持兼容。
3. 作为唯一/末尾 body form 的字符串不被误判为文档字符串。
4. host 回归直接执行生产函数，并包含关闭 `:permit-docstring` 的变异负例。
5. 验证通过后移除源代码 FIXME；codegen 与 cold-image 证据未补齐前，工作项保持
   `active`。
