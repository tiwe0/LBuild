# TF-WI-0043 — 常量传播中的浮点操作数顺序

- **基线标记：** `TF-occ-5561274a2b65df3c63830c60`
- **代码事实源：** `Lambda64/compiler/constprop.lisp:276-360`
- **风险：** critical
- **要求测试层：** host、codegen、cold-image

## 目标

常量传播的 `:commutative-arithmetic` 分支只在所有操作数已证明为非浮点时重排
操作数。浮点加法和乘法每一步都会舍入，不能按结合律移动常量；完全常量的表达式
仍按原始顺序折叠。

## 先测试证据

新增 `Lambda64/tests/host/test-compiler-constprop-float-order.sh`，验证生产源包含
浮点类型守卫、完全常量例外和安全重排谓词；变异负例移除守卫，必须被测试拒绝。

实现前基线包含 `Float arithemetic is non-commutative.` 注释但没有任何守卫，测试会
拒绝该状态。

## 验收标准

1. 未知或可能为浮点的操作数不触发常量重排。
2. 已知非浮点操作数保留原有常量传播优化。
3. 全部为常量的表达式按原始顺序折叠，不改变结果或异常行为。
4. codegen、cold image 验证待 Quicklisp 与完整构建环境恢复后执行，工作项保持
   `active`。
