# TF-WI-0377: Complete LLF character serialization

## Scope

This work item removes the former character-serialization restriction in
`Lambda64/system/file-compiler.lisp` without changing the compact encoding for
ordinary characters.

## Required behavior

`save-character` encodes every 21-bit implementation character code in one to
four UTF-8-shaped bytes. `llf-unicode-scalar-code-p` guards the numeric Unicode
range before calling `code-char`, and `llf-compact-character-p` is shared by
the string and character serializers. Direct characters with attributes retain
the existing `+llf-character-with-bits+` representation only when `code-char`
accepts the base code. Rejected Unicode noncharacters and codes from
`#x110000` through `#x1FFFFF` are reconstructed through `%%make-character`,
preserving both the arbitrary code and all four attribute bits. Strings
containing either attributed or implementation-only characters use the same
allocation/backlink/initialization path rather than the compact string record.

## Acceptance evidence

`Lambda64/tests/host/test-system-file-compiler-semantics.sh` directly extracts
and executes the production string and character methods. A host adapter maps
real host characters to Mezzano codes and attribute bits, covering `#xFFFF`,
`#x10000`, `#x110000`, and `#x1FFFFF`, plus attributed and noncompact strings.
The mutation-negative pass rejects an all-compact string predicate and a
character method that checks only `<= #x10FFFF`. The pre-change `HEAD` source
fails the focused contract gate with exit 1; the implemented source passes.

A cold Mezzano image is still required to execute the noncharacter and modified
character round trip with native immediate characters, so status remains
`active`.
