# TF-WI-0167: TCP Reno congestion recovery contract

## Required behavior

TCP tracks congestion window, slow-start threshold, and duplicate ACK count.
New ACKs grow the window through slow start or additive increase. Three
qualifying duplicate ACKs halve the flight threshold, fast-retransmit the first
unacknowledged segment, and enter fast recovery. The fourth and subsequent
duplicate ACKs keep the duplicate count and congestion window capped at that
transition; a new ACK exits recovery. Retransmission timeout resets the window
to one MSS and applies exponential RTO backoff.

## Evidence

The host test executes production congestion helpers and the full
`RETRANSMIT-TIMER-HANDLER`, verifying retransmission and exponential RTO
backoff. Three duplicate ACKs enter fast recovery and retransmit, while a new
ACK exits recovery; no-op mutants for both transitions are rejected. Once abort
intent is published, the retransmit handler emits nothing. Because this stack
does not transmit an extra segment for every later duplicate ACK, the duplicate
counter and congestion window remain capped at the third-ACK recovery
transition; restoring unconditional fourth-plus inflation is a rejected mutant.
Congestion behavior under real loss/reordering remains guest/network work.
