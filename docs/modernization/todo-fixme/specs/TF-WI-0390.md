# TF-WI-0390: FORMAT escape-upwards predicates

## Scope

This specification closes the corresponding baseline marker formerly present
in `Lambda64/system/format.lisp` without narrowing Common Lisp `FORMAT`
argument-consumption or error behavior.

## Required behavior

`~^` implements the zero-, one-, two-, and three-parameter escape predicates. It terminates the active format or iteration without leaking a throw, while `~:^` checks and exits the enclosing iteration argument domain. An escape internally transfers the current, unconsumed argument tail, but a compiled `FORMATTER` exposes exactly one return value: that tail. Bounded iteration respects its count and final-separator idioms do not leave trailing separators.

## Acceptance evidence

`Lambda64/tests/host/test-system-format-semantics.sh` loads the repository
implementation rather than the host `FORMAT` and covers this directive together
with direct compiled-`FORMATTER` checks for true, false, and exhausted-argument
escape conditions, including the public single-value boundary. Against the
pre-change `HEAD` source, the focused command exits non-zero; its first failure
is grouped integer width (`"      1,234"` instead of `"     1,234"`). Against
the implemented source, the focused command passes.

The work item requires cold-image and integration levels in addition to the
host fixture. Guest execution against Mezzano streams and the late pretty
printer has not yet been recorded, so this specification remains `active`.
