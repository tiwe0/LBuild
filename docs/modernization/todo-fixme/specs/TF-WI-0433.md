# Package-system lock ownership boundary

`call-with-package-system-lock` uses a non-recursive mutex with explicit
ownership detection. Nested package operations execute directly when the
current thread already owns the lock; otherwise the outer call acquires it.
Error handling may temporarily release and reacquire the same lock while the
debugger runs. The implementation comment documents this intentional boundary;
untangling all package call paths remains a separate architectural change.

The focused host fixture checks the ownership and mutex anchors and rejects a
mutation removing the ownership check.
