# TF-WI-0433: XP standard FORMAT justification

## Scope

This work item closes the baseline marker in `Lambda64/system/xp-format.lisp`
for standard `~<...~>` blocks. Logical blocks ending in `~:>` retain their
existing XP-specific route.

## Required behavior

The XP compiler preserves the standard justification parameters `(mincol,
colinc, minpad, padchar)`, preserves colon and at-sign placement modes, and
consumes the current XP argument tail exactly as the regular formatter does.
It delegates section sizing, distribution, and optional `~:;` overflow clauses
to `MEZZANO.FORMAT::FORMAT-JUSTIFICATION` while dynamically binding the XP
character stream as `*STANDARD-OUTPUT*`; this keeps buffering and line-layout
behavior in XP rather than a temporary output stream.

## Acceptance evidence

`Lambda64/tests/host/test-system-xp-format-justification.sh` loads the real XP
compiler, generates a formatter through `FORMATTER-FN`, and executes its
standard-justification handler. It verifies interior, leading, trailing,
custom-padding, overflow-clause, `V`/`#` parameter, `~:*` argument-base, and
`~^` escape behavior, including terminating the enclosing XP control sequence
as the early formatter does, and `~:^` against an enclosing `~:{...~}`
iteration's remaining groups or the initial argument base outside iteration;
it also rejects invalid closing `~@>` and a top-level `~;`. Mutation negatives
cover the shared engine, XP output and escape bindings, both colon-argument
contexts, defaults, modifier forwarding, closing at-sign validation, and the
out-of-context separator error.

The previous code concatenated compiled fields without applying justification
parameters. Host verification is recorded; cold-image and integration coverage
remain outstanding, so this specification remains `active`.
