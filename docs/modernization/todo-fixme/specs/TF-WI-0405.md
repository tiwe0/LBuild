# TF-WI-0405 — reader 的 Unicode invalid character 检查

- **基线标记：** `TF-occ-820103d8fd21c894fb63c092`
- **代码事实源：** `Lambda64/system/reader.lisp:150-156`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

reader 的 `invalidp` 不能只枚举 ASCII 控制字符。对 readtable 中没有语法定义的
字符，应依据 `graphic-char-p` 判断是否为不可读的 Unicode 控制/格式字符；可打印的
Unicode 字符继续作为 token 内容正常处理。

## 先测试证据

新增 `Lambda64/tests/host/test-system-reader-unicode-invalid.sh`，检查 invalidp 保留
readtable 语法判断并调用 `graphic-char-p`，同时确认恢复固定 ASCII 列表的变异会被拒绝。

## 验收标准

1. 未定义语法的 Unicode 非 graphic 字符被报告为 invalid。
2. Unicode 字母、数字、标点和空格分隔符等 graphic 字符不被误拒绝。
3. 既有 ASCII 控制字符行为保持不变。
4. codegen、cold image 和 integration 验证待完整构建环境恢复后执行，工作项保持
   `active`。

## 当前证据

```sh
bash -n Lambda64/tests/host/test-system-reader-unicode-invalid.sh
bash Lambda64/tests/host/test-system-reader-unicode-invalid.sh
```

host 合约测试通过，并确认固定 ASCII 列表的变异会失败。完整 codegen、cold image 与
integration 尚未运行。
