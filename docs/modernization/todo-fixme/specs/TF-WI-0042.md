# TF-WI-0042 — non-null lexical environment compilation

- **Baseline marker:** `TF-occ-48f973d53729e74ebf122ff8`
- **Code source of truth:** `Lambda64/compiler/compiler.lisp:138`
- **Risk:** critical
- **Required test levels:** host, codegen, cold-image

## Current boundary

`mezzano.compiler:compile` accepts a function object only when
`function-lambda-expression` returns a null lexical environment.  A non-null
environment is rejected before lowering, because the compiler's environment
representation and closure conversion are target-specific.  This is an
intentional safety boundary: silently compiling the lambda expression while
discarding its captured bindings would change observable semantics.

## Required completion evidence

1. Define how lexical variables, symbol macros, declarations, and captured
   function bindings are serialized into the target closure representation.
2. Add host tests for a function that captures a lexical binding, including a
   mutation case proving that dropping the environment is rejected.
3. Add codegen and cold-image coverage proving the generated closure accesses
   the captured slots with the target ABI.

Until those tests and the closure ABI specification exist, the marker remains
`active`; replacing the diagnostic with an unconditional compilation path is
not a valid fix.

## Implementation gate (2026-09-01)

This work item remains **active**. The current compiler deliberately rejects a
non-null environment before `compile-lambda`; removing that guard without a
closure-ABI and cold-image proof would silently discard captured bindings.
No source change is authorized by this specification until the required host,
codegen, and cold-image evidence is available.
