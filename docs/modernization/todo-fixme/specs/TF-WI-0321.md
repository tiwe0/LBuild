# TF-WI-0321 — `ATOMIC-DECF` 与最小 fixnum

- **基线标记：** `TF-occ-065fede0475bc4e576eb4919`
- **代码事实源：** `Lambda64/system/cas.lisp:203-216`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`atomic-decf` 必须接受任意 fixnum delta，包括 `most-negative-fixnum`，并按其文档的
fixnum 宽度二补码语义包装结果。该特殊值不能直接取负：其数学相反数不再是 fixnum。
实现必须仅求值一次 `delta`，普通 delta 仍传递给 `atomic-incf` 的负值。

## 先测试证据

新增 `Lambda64/tests/host/test-system-atomic-decf-minimum.sh`，从生产源提取实际
`atomic-decf` 定义，并以最小 `atomic-incf` 替身验证宏展开后的加法 delta。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-atomic-decf-minimum.sh
```

失败并报告：

```text
ATOMIC-DECF did not preserve MOST-NEGATIVE-FIXNUM's wrapping delta
```

这证明旧实现对最小 fixnum 直接求负，不能形成所需的 wrapping addend。变异负例恢复
该直接取负路径；测试必须拒绝变异。

## 验收标准

1. `delta` 为 `most-negative-fixnum` 时传给 `atomic-incf` 的 delta 保持该 fixnum 的二补码位模式。
2. `delta` 仅求值一次。
3. 常规负 delta 的反转行为保持不变。
4. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。
