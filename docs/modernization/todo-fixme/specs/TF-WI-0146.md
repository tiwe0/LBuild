# TF-WI-0146: Font modifier-bit normalization contract

## Scope

This specification resolves the character-bit gap in
`Lambda64/gui/font.lisp:143`, at the boundary from GUI input characters to
glyph lookup and rasterization.

## Required behavior

Character modifier bits (`:control`, `:meta`, `:super`, and `:hyper`) are input
state, not a part of a glyph's visual identity. `character-to-glyph` must
normalize a modifier-bearing character to a zero-bit character with the same
Unicode code point before using the glyph cache, TTF lookup, or Unifont
fallback.

Consequently, a modified character and its ordinary counterpart share one
cached glyph, that glyph records the ordinary character, and the fallback
receives only zero-bit characters. Existing glyph selection, missing-glyph
replacement, ordinary character rendering, cache synchronization, and metrics
must remain unchanged.

## Test-before evidence

Before the implementation, the focused host fixture completed its behavioral
facade but failed its representation-level assertion:
`character-to-glyph does not explicitly normalize modifier bits`. The old
method forwarded the original modifier-bearing character to
`sys.int::map-unifont-2d`, despite that API requiring `char-bits = 0`.

## Acceptance evidence

`Lambda64/tests/host/test-font-modifier-bits.sh` executes the real method with
a modifier-bearing host character adapter. It verifies shared ordinary/modified
TTF cache entries, zero-bit fallback input, unchanged missing-glyph replacement
order, and explicit source-level normalization. The latter check is necessary
because host Common Lisp characters cannot encode Mezzano modifier bits.

The focused host test, `make lisp-style-check`, and a whitespace-clean diff are
required for this slice. The work-item ledger additionally requires guest
evidence; none is recorded here, so the item must not be marked verified until
image-level rendering evidence exists.
