# TF-WI-0376: LLF source pathname record

## Scope

This work item records the compile input pathname in every LLF emitted through
`write-llf-header` while retaining compatibility with the current fixed-prefix
loader.

## Required behavior

After magic, version, and architecture, the writer emits the input namestring as
an ordinary LLF string followed by `+llf-drop+`. Existing loaders consume and
discard this metadata before executing compiled forms, so the stack and fixed
header checks remain unchanged. Binary inspection can recover the producing
source pathname.

## Acceptance evidence

`Lambda64/tests/host/test-system-file-compiler-semantics.sh` executes the
production header writer, checks the unchanged magic/version/architecture
prefix, decodes `source/test.lisp`, and verifies the following drop command.
The pre-change `HEAD` source fails the focused contract gate with exit 1; the
implemented source passes.

Cold-image loading and guest-side source metadata inspection remain unrecorded;
this specification therefore remains `active`.
