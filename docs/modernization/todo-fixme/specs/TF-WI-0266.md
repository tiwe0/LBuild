# TF-WI-0266: Atomic supervisor GPT integrity and bounds validation

## Scope

This specification closes the GPT integrity-validation requirement formerly
marked in `Lambda64/supervisor/partition.lisp`.

## Required behavior

After matching `EFI PART`, the supervisor must validate a header before
accepting it: the exact supported GPT 1.0 revision, header size, header CRC-32
with the CRC field treated as zero, reserved field, non-zero disk GUID, current
and backup LBA placement, usable-LBA ordering, entry count and size, and
entry-array range. Primary headers must identify LBA 1 as current and the final
disk LBA as backup; backup headers use the inverse placement. Entry size must be
`128 * 2^n`, rather than merely aligned. The supervisor then validates the
CRC-32 of the exact entry-array byte length, excluding sector padding.

A used entry has a non-zero type GUID and must also have a non-zero unique GUID
and an inclusive `first-lba..last-lba` range contained in the header's usable
range and disjoint from every other used entry. All header, array, and
used-entry checks finish before any partition is registered, so a bad later
entry or CRC cannot expose a partial disk list.

When the primary header or its entry array fails validation, the supervisor
reads and independently validates the backup header at the final LBA and its
own entry array. If neither copy validates, GPT detection returns false and
leaves the existing MBR/ISO-9660 fallback path available. A protective MBR
entry of type `#xEE` is GPT metadata and is never registered as a normal
partition, including after both GPT copies fail. Other supported MBR entries
remain available, and a valid empty GPT remains a recognized table.

CRC uses the GPT/IEEE reflected polynomial `#xEDB88320`, initial value
`#xFFFFFFFF`, and final XOR `#xFFFFFFFF`.

## Acceptance evidence

`Lambda64/tests/host/test-supervisor-partition-gpt-validation.sh` covers valid
multi-sector input, bad header CRC, bad entry-array CRC after an otherwise valid
entry, malformed header/table geometry, unsupported minor revision and
160-byte entries, a primary backup pointer not at the final LBA, entries outside
the usable range or overlapping each other, atomic non-publication, recovery
from a corrupt primary using a valid backup, protective-MBR suppression when
both GPT copies fail, and successful ordinary MBR fallback after GPT rejection. The
pre-implementation fixture failed before these integrity checks were present;
the focused host test passes after implementation. Required cold-image and
guest integration evidence against real primary/backup GPT media remains open,
so this specification stays `active`.
