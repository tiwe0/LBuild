# TF-WI-0144: Compositor resize-origin grab-region contract

## Scope

This specification closes the resize-origin defect at
`Lambda64/gui/compositor.lisp:955` in the compositor's `resize-event` handler.

## Required behavior

The cursor grab rectangle is expressed in window-relative coordinates. When a
resize origin moves the window's left or top edge, the grab rectangle must be
translated by the inverse window-origin displacement so that it remains
attached to the same screen-relative edges. Axes whose window origin does not
move retain their existing grab coordinates. Midpoint resizing applies the same
rounding as `updated-window-origin-for-resize`.

After translation, all four grab coordinates must be clamped independently to
the inclusive ranges `0..new-width` and `0..new-height`. This includes minimum
one-pixel window sizes. An inactive grab must not cause the compositor to read
or initialize the grab-coordinate slots. Resize event delivery and drag-state
semantics are unchanged.

## Acceptance evidence

`Lambda64/tests/host/test-compositor-resize-origin.sh` must exercise all four
corner origins, midpoint resizing, distinct horizontal and vertical anchoring,
minimum-size clamping, an inactive grab with unbound coordinate slots, and a
post-delivery grab update. The latter proves that the implementation translates
the current grab state after the non-blocking resize notification rather than
restoring a stale pre-notification snapshot. The focused host test, `make
test-fast`, and a guest compositor resize test are required before this item may
be marked verified.
