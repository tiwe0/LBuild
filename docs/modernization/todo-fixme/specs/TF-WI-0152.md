# TF-WI-0152: Virgl resource scatter/gather backing contract

## Scope

This specification resolves discontiguous DMA backing for virgl buffers and
textures in `Lambda64/gui/virgl/virgl.lisp`.

## Required behavior

Buffer and non-host-only texture allocations may be physically discontiguous.
Resource attachment builds one complete
`VIRTIO_GPU_CMD_RESOURCE_ATTACH_BACKING` request from every DMA scatter/gather
extent rather than reading only the allocation's first physical address.

The request uses the 24-byte virtio-gpu control header, resource ID and entry
count at bytes 24 and 28, and 16-byte memory entries beginning at byte 32. Each
entry carries a 64-bit address, a 32-bit length, and zero padding. Because the
protocol length field is 32 bits, a larger physical extent is split into
contiguous address chunks of at most `#xFFFFFFFF` bytes. A zero-length DMA
allocation retains one zero-length compatibility entry. The encoded entry
count must fit the protocol's 32-bit field.

The request itself is DMA-backed and submitted through the same scatter/gather
virtqueue path as optimized command buffers. It is released after either
success or device failure. Direct virtqueue descriptors are used, so an
attachment with more request extents than the control queue can reserve fails
explicitly and without publishing a partial descriptor chain.

## Test-before evidence

`Lambda64/tests/host/test-virgl-scanout-backing.sh` initially exited with status
1 because the memory-entry encoding implementation was absent. The old buffer
path passed one physical address to the fixed one-entry driver API, and the old
texture path forced `:contiguous t` while retaining an explicit discontiguous
buffer TODO.

## Acceptance evidence

The focused host test feeds the real backing encoder two physical extents,
including one larger than the 32-bit entry length. It verifies the full request
header, exact 80-byte request length, three entry addresses and lengths,
per-entry padding, temporary request release, device-error propagation, and
zero-length compatibility. Structural assertions prove both buffer and texture
construction use the common helper and that texture allocation no longer
forces contiguity.

The ledger additionally requires guest execution. No real virtio-gpu/virgl
resource creation and transfer using a deliberately fragmented allocation has
been recorded, so this item remains active pending image-level evidence.
