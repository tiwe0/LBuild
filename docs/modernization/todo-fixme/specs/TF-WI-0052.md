# TF-WI-0052: dynamic-extent array initial-element normalization boundary

## Scope

Document the two historical TODO/FIXME notes in
`Lambda64/compiler/dynamic-extent.lisp` where dynamic-extent array lowering
handles initial elements.

## Contract

`make-array` cross-compilation normalizes an omitted `:initial-element` to the
specialized array definition's zero element before constructing
`make-array-with-known-element-type`. The dynamic-extent pass therefore cannot
recover whether the keyword was omitted from the AST and intentionally treats
the normalized value as an explicit fill request. Zero-valued arrays use the
allocator's zeroed storage; non-zero values are written to every element.
Adding a presence bit to the AST is a separate compiler representation change.

## Verification

`Lambda64/tests/host/test-compiler-dynamic-extent-array-boundary.sh` checks the
normalization and explicit-fill anchors and rejects reintroducing the stale
markers.
