# TF-WI-0409 — `restart-case` signal/error/warn 快路径

- **基线标记：** `TF-occ-a7dbd595cec1031cba2cebbf`
- **代码事实源：** `Lambda64/system/restarts.lisp:146-192`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

当 `restart-case` 的 restartable form 展开为 `signal`、`error`、`cerror` 或 `warn`
时，直接构造 restart 对象并通过 `%restart-bind` 建立动态绑定，同时把同一组对象
关联到 condition。该快路径不再递归展开另一个 `restart-case`，也不调用
`find-restart` 查找刚刚建立的对象；普通非诊断 form 的展开保持不变。

## 先测试证据

新增 `Lambda64/tests/host/test-system-restarts-fast-path.sh`，检查快路径包含直接
`make-restart`/`%restart-bind` 和 condition association，并确认恢复 `restart-bind`
或保留 `FIND-RESTART` 的变异会被拒绝。

## 验收标准

1. 四类诊断 form 的 restart handler 仍能接收参数并跳转到对应 clause body。
2. `find-restart`、`compute-restarts` 看到的对象与触发 condition 的关联保持一致。
3. 非 `signal`/`error`/`cerror`/`warn` 的 `restart-case` 继续走原有 tagbody 路径。
4. codegen、cold image 和 integration 验证待完整构建环境恢复后执行，工作项保持
   `active`。
