# TF-WI-0050 — cross-file compiler-macro expansion

- **Baseline marker:** `TF-occ-bfa749871078bc085200c1c7`
- **Code source of truth:** `Lambda64/compiler/cross-file-compiler.lisp:130-145`
- **Risk:** critical
- **Required test levels:** host, cold-image, integration

## Objective

`x-compile-for-value` must lower the same fully expanded form that the normal
file compiler uses. It repeatedly performs ordinary macro expansion and then
`compiler-macroexpand-1` in the active lexical environment. A compiler-macro
expansion can expose another ordinary macro, so the process returns to ordinary
macro expansion until neither expander changes the form.

## Test-first evidence

Before the implementation, the focused host test failed with the old
single-`macroexpand` lowering:

```text
compiler-macro expansion chain did not complete: ((NIL 1)
                                                    (:FUNCALL-N ORIGINAL 1))
```

`Lambda64/tests/host/test-compiler-cross-file-macros.sh` starts from an
ordinary macro, has its compiler macro produce a second ordinary macro, and
asserts that lowering emits a call to the final form. Its mutation case stops
after the compiler-macro result and must fail, proving that re-entry into
ordinary macro expansion is required.

## Current evidence

```sh
bash Lambda64/tests/host/test-compiler-cross-file-macros.sh
```

The focused test and its mutation check pass. Cold-image and QEMU integration
coverage remain pending as part of the repository-wide modernization audit, so
