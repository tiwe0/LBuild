# TF-WI-0358 — `&ENVIRONMENT` 的位置和绑定名校验

- **基线标记：** `TF-occ-2b2085c2728320d6cbfca6b7`
- **代码事实源：** `Lambda64/system/defmacro.lisp:208-245`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

`fix-lambda-list-environment` 继续允许单个顶层 `&environment` 出现在 macro lambda-list
的合法分段位置，并保留其原有的去除与绑定名返回行为。它必须拒绝缺失、`nil`、非 symbol
或 dotted-tail 形式的 environment binding；`&whole` 仍必须位于 lambda-list 最前。

## 先测试证据

新增 `Lambda64/tests/host/test-system-defmacro-environment-placement.sh`，它从生产源加载
实际规范化函数，覆盖 `&whole`、required、optional、rest、key、aux 和 dotted-rest 边界的
合法位置。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-defmacro-environment-placement.sh
```

失败并报告：

```text
non-symbol &ENVIRONMENT binding was accepted
```

说明旧实现仅检查了缺失或 `nil`，会把 list 这样的非法 binding name 传给下游展开器。
回归还锁定重复 `&environment` 与 `&environment` 位于 `&whole` 前的拒绝路径；变异负例
移除 `symbolp` 检查，必须被拒绝。

## 验收标准

1. 顶层合法位置的 `&environment` 被移除后，剩余 lambda-list 结构不变且返回原 binding。
2. 缺失、`nil`、非 symbol 和 dotted-tail binding 均发出 `invalid-macro-lambda-list`。
3. 重复 `&environment` 及其位于 `&whole` 前的无效次序继续被拒绝。
4. cold image 与 QEMU integration 留待完整环境验收；在此之前工作项保持 `active`。
