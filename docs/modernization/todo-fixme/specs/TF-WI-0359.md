# TF-WI-0359: Preserve pending footholds across prompt return

## Scope

`%call-with-prompt` reenables footholds after restoring the caller stack. At
that point the function may still be carrying multiple values in the x86-64
register protocol; invoking `run-pending-footholds` directly would overwrite
those values.

## Current boundary

Pending footholds are deferred across the return boundary. They are expected
to run at the next supervisor safepoint after the multiple-value state has
been preserved. Host coverage locks this deferral contract; no cold-image or
integration evidence currently proves a safe save/restore implementation.

## Required evidence

Add host, cold-image, and integration tests that queue a foothold while a
prompt returns multiple values, then verify ordering and value preservation.
Remove the source marker only after those paths agree.
