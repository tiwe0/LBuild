# TF-WI-0352 — 冷启动 `PEEK-CHAR` 的字符定界模式

- **基线标记：** `TF-occ-707561cf15270060e440d403`
- **代码事实源：** `Lambda64/system/cold-start.lisp:56`
- **风险：** high
- **要求测试层：** host、cold-image、integration

## 目标

在 CLOS 和完整 stream 子系统尚未加载的冷启动阶段，实现
`(peek-char <character> stream)`：持续读取直到目标字符，随后将目标字符
回退到流中并返回它。前置字符必须被消费；下一次读取必须仍然得到目标字符。

该行为与完整 `Lambda64/system/stream.lisp` 的字符分支保持一致，不改变既有的
`NIL`（查看下一个字符）和 `T`（跳过空白）模式。

## 先测试证据

先新增 `Lambda64/tests/host/test-system-cold-start-peek-char.sh`。它从生产
`cold-start.lisp` 提取并执行实际 `PEEK-CHAR` 定义，使用具备单字符回退能力的
冷流替身覆盖 `NIL`、`T`、一般字符和空白字符定界符。

实现前运行：

```sh
bash Lambda64/tests/host/test-system-cold-start-peek-char.sh
```

在输入 `"ab=c"` 调用 `(peek-char #\= stream)` 时失败并报告
`TODO: character peek.`。

## 验收标准

1. 字符定界模式消费目标字符前的所有字符，找到目标后返回并回退该目标字符。
2. 回退后的一次 `cold-read-char` 返回同一目标字符，之后的字符顺序保持不变。
3. `NIL` 和 `T` 模式维持原有查看/跳过空白语义；字符定界符本身可以是空白。
4. 宿主机回归直接执行生产定义，并包含使 `characterp` 分支不可达的变异负例。
5. 完成 host 证据后，后续以 cold image 和 QEMU integration 覆盖真实冷启动路径；
   在这两层证据补齐前，工作项保持 `active`。
