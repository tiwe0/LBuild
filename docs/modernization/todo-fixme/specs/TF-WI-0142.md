# TF-WI-0142: Two-dimensional BITBLT overlap contract

## Scope

This specification closes the overlapping-copy defect at
`Lambda64/gui/blit.lisp:108` for `2d-array-bitblt`.

## Required behavior

When source and destination expose the same underlying UB32 storage and their
post-clipping rectangles intersect, the destination pixels must equal the
pixels obtained by sampling the *entire source rectangle before any destination
pixel is written*. This is two-dimensional `memmove` semantics.

The implementation may use a snapshot or a provably safe traversal. It must not
select a line-only traversal that corrupts a later source row or column. When
storage differs or rectangles do not overlap, the existing non-overlap path
must remain applicable. Existing clipping, coordinate, and pixel-format
semantics are unchanged.

## Acceptance evidence

`Lambda64/tests/host/test-gui-bitblt-overlap.sh` must verify upward/downward
vertical overlap, left/right horizontal overlap, overlapping displaced views of
the same backing vector, same-storage non-overlap, and a clipped negative
coordinate case. The focused host test and `make test-fast` are required before
this item may be verified.
