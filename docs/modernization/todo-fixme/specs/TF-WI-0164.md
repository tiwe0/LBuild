# TF-WI-0164: TCP listener synchronization contract

## Required behavior

Each listener owns a mutex and a closed flag. Passive-open reservation,
half-open hash mutation, backlog accounting, promotion to the accept mailbox,
accept completion, and listener close are serialized. Removal is idempotent;
promotion retains the backlog slot until `TCP-ACCEPT`, while failure or timeout
releases it immediately. A SYN racing listener close cannot create new work.

## Evidence

The focused host test directly executes production `TCP4-OPEN-PASSIVE`,
`TCP-ACCEPT`, and `CLOSE-TCP-LISTENER`. Deterministic mailbox/lock
interleavings prove that close wins over a received-but-not-returned connection,
all pending classes are aborted, and backlog accounting reaches zero. A mutant
that permits passive opens on a closed listener is rejected. True multi-CPU
scheduling remains guest validation.
